### Added

- The hand-over card has a `quality` row, read from the last `dialecte rules` record of the worktree: `! quality  2 duplicate reads · 3 shared exports changed (to read ↓)` with a `quality` section after `tdd` listing them (ten per kind, then `… <n> more (dialecte rules --base <short> --json)`), every one counted in the verdict's declarations to read. A public export left without docs and not opted out fails the row (`✗ quality  1 public export without docs: <route>`) and blocks the card; an opted-out finding is counted (`1 allowed`), never listed. A record of another tree, or whose base the lot no longer has, reads `! quality  record of another tree (dialecte rules)`: never stale, never blocking, nothing counted; no record reads `! quality  never run on this tree`. A `--base` record shows its lists `(since <short>, --base)` only when its base is the lot base or older, and never sets nor clears the docs row: that row stays the one of the last run without `--base` on the same tree (`docs: never run on this tree` without one, `docs: record of another tree` when its base moved). The card's `--json` holds `quality`. A public entry removed while a page still names it is a note of `rules`, never a docs finding: it neither fails nor counts. The row is left out for a package with no `package.json`, and where `dialecte rules` would judge nothing (no lot or base-branch base, no record).
- The pull request body's risk part lists the base-aware findings under the risk line, judged on the committed head against the body's own base (uncommitted work ignored, no record read): `Quality: <counts> (since <short>)`, one line per finding not opted out as `dialecte rules` words it, ten per kind then `… <n> more (dialecte rules --base <short> --json)` (a public export without docs marked `✗`), then the notes `rules` prints: `public API: <route> removed: still named by <pages>` (once, never a `✗` line), `! public API unknown (<why>)`, `aliases changed: base edges read with the tree's`. The package.json, the public API index, the export sources and the doc pages are all read at the head. `Quality: not judged (<why>)` when the head holds no `package.json`, holds one that does not parse (`package.json does not parse`), or git cannot read the base. The duplicate reads compare with the package's own api indexes the head holds, whatever its `exports` map, as `dialecte rules` does on the same tree. Its lines are checked as public text like every record text.

### Changed

- `dialecte-quality.json` is schema 2: every finding is kept with `allowed` (true when an opt-out silenced it); a schema 1 record reads as none. A `--base` run carries the docs findings of the last run without `--base` as `lotDocs`, with that run's tree and base.
