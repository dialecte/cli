### Fixed

- `rules` without a gate base, `contrib`'s rules row and the empty-tree gate base (`gate --release`) judge a store lot against its lot base read from git, its fork point from the base branch, or from its parent's line while the lot it was started on is open, instead of the base recorded at `lot start`. A lot rebased onto a newer main, or one that merged main, no longer counts main's lines since its cut as its own, and a stacked lot no longer counts its parent's. The base line still names the lot (`rules: base <sha> (the lot <name>)`).
- A lot base that cannot be read, such as a stack parent the store does not hold, gives no base and the line `rules: no base (<why>)`, never the base branch's merge-base, which would take in the parent's commits.
- A lot with no base branch found and none configured takes one shared fallback: the newest of the commit it recorded at its start, when HEAD holds it, and a release tag of the package that descends from that commit, else no base. HEAD is never its base, so its committed lines count as added. `rules`, `lot risk` and the design gate's shared areas all read it.
- The design gate reads a lot's shared areas at its lot base, else at that fallback, never at HEAD: a lot that drops an area from its `package.json` is still held to it, in `lot design`, `lot forecast` and the pull request.
- `gate --release` and `contrib`'s rules row say `rules: no base (<why>)` too when the lot base cannot be read, instead of judging with no base silently.
- `lot risk`, and the risk class `lot start` and the views derive for a store lot, are derived against the lot base, else the shared fallback, so a file main added since the cut is no reason and the lot's own committed files always are. A store lot whose recorded base commit git cannot read now gets its class derived against the lot base (the hand-over card's effort line read `risk class unknown` there); a lot with neither a lot base nor a fallback is not derived, with `! risk class not derived: no base: no lot base (<why>) and HEAD does not hold the commit recorded at its start (<commit>)`.
