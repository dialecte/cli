### Fixed

- A cli older than the version a repository asks for runs no `dialecte lot` verb: it exits 2, naming the path it was started by and its real path, its version, the floor and where the floor came from (`--json`: `{ error, next: null }`), and writes nothing. The floor of a package is the cli repository's own version, else the lowest version its `@dialecte/cli` pin admits. A pin with no lower bound (`*`, `workspace:*`, `<2.0.0`, an `||` alternative without one) asks for no floor; a pin that is no semver range (`file:`, `link:`, a path or url, `git+`, a dist-tag, `workspace:^` or `workspace:~` with no version after them) asks for the installed cli's version. The repositories read are the current folder's package and those of each lot or brief the command line names; the highest floor decides. When the working tree's floor would refuse, the base branch's tip is read and the cli is refused only below both, so the main checkout's cli still lands a release or pin-bump lot. Equal or newer runs; help is never refused. The refusal hints the repository's own cli, `npm install` for a stale install, or `git -C <checkout> pull` for a cli checkout behind its release.
- The test suite no longer depends on a machine-global `@dialecte/cli`: npm's global prefix is an absent folder of the suite's own, so `npx --no-install` never finds a globally installed cli.
