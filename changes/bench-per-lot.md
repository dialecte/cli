### Changed

- **Breaking:** `dialecte bench` measures the change against the base it goes onto, fresh, and writes no baseline any more: no `benchmarks/types/<version>/baseline.json` is read or written. The base is `--base <ref>` (its merge-base with HEAD), else the base handed in `DIALECTE_CHANGE_BASE`, else the order `dialecte rules` uses (the lot base of a store lot, the merge-base with the base branch, the last release tag). Both trees are measured with the head's compiler on one checker, one run per scenario; the base is exported into a scratch folder and removed after.
- **Breaking:** a scenario more than 5% over its base fails `dialecte bench --check` unless the change explains it: a line `- Type cost: <why>` it adds to its changelog fragment, or `Type cost: <why>` in its no-entry note. A line already at the base explains nothing.
- **Breaking:** `dialecte bench` exits 2 on every refusal (a base that cannot be read or is no commit, a lot with no base, no base with `CI` set under `--check`, a `node_modules` that does not install the lock, no version, a base tree that cannot be made or measured, method discovery failing at the head with `--check`); exit 3 is gone, and so is the `RUNS` variable.
- The CI template's type-perf job checks out the base the change goes onto and hands it to the bench in `DIALECTE_CHANGE_BASE` (the merge queue's base sha, else `HEAD^1`), skipped on a dispatch; `dialecte contrib` hands its type-bench step the base of the change, and a rehearsal with no base does not run that step.
