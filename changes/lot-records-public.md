### Added

- A lot's `review.jsonl`: the public rows of its review, what a pull request may show. One `finding` row per row of the findings ledger (`id`, `round`, `severity` as `blocking` / `should-fix` / `nit`, `file`, `state` as `open` / `fix-to-verify` / `fixed` / `accepted` / `logged`, `closedBy: { round }` for a fixed one), then one `verdict` row per review by time: a `reviewer` or `independent-reviewer` station end carrying a verdict (`by: { kind: "station", station, round }`, the `vendor` and `model` its end or its start gave), and a `lot verify` line (`by: { kind: "verify", name }`, verdict `verified`). `lot finding`, `lot decide`, `lot verify` and a review station's `lot station end` derive it from those sources and write it whole, so a ledger edited by hand is read again at the next verb. Nothing private is copied: never a finding's text, a fix's note, an acceptance's reason, a logged finding's where or a verify note; a `file` (its `./` dropped) is kept only when git lists it in the lot's worktree, tracked or untracked and not ignored, or at its base (a plan, an ignored or linked file, an absolute or a `..` path is left out); the state is read from a row's last cell, and a cell the ledger parser cannot read is left out, never guessed. A `vendor` or `model` that is not one plain word, or that fails the check `lot verify` puts on its `--by`, is left out, so is a station end whose verdict is outside the station vocabulary, and a `verify.jsonl` line written by hand whose `by` fails that check keeps its row without the name; when the lists cannot be read, no name, vendor or model is kept. A retried station end writes the record again. A record that cannot be written adds a `! review.jsonl not written: <reason>` line (a `warning` field under `lot station --json`); the verb's own write stands. `lot verify` refuses a `--by` holding a path, a link, a reference or an entry id of the plans that hold the lot (`lot verify: --by holds a <label>: nothing written`, or `--by not checked: <reason>` when the lists cannot be read): it reaches the record.
- A brief takes `summary` (optional: one public sentence, one line, at most 200 characters) and `issue` (optional: a positive integer, the issue the lot's pull request closes). `lot start` refuses a summary holding a path, a link or a `file:line` (`summary holds a path or a link`), or a plan tag, ticket number, standard citation, a reference the package declares, a contributor's consumer name, a forbidden word or an entry id of the plans that hold the lot (`summary holds a <label>`, the text never printed), and an issue that is not a positive integer. The plans that hold a lot are the brief's `plan` and each plan marked on the machine (`dialecte plan mark`) one of whose entries names the brief's branch; an entry id is matched case-insensitively, as a word or as a part of a word split at `-`, a one-character id as written. `goal` stays the brief's private line.
- A lot's `tests.json`: the public record of its tests. Its `tdd` part (`at`, `head` and `stateHash` of the tree it was read on, `cases` with `file`, `name`, `project` when not the default one, `status` and `flags`, and `counts` by status) is written at `tdd green` from the cases of the change as `tdd status` reads them; its `gate` part (`mode`, `at`, `head`, `stateHash`, `tests`, `testFiles`) by a gate run in the lot's own worktree, from the newest gate record one of whose steps counted tests. Each writer replaces its own part and keeps the other, the file written whole; never a receipt's reason or message. A part with no source is absent, and with neither the file is not written. `tdd green` reads the cases again once its receipts are written (a `tdd green: tests.json` progress step), only in a lot's own worktree. Neither part is written from a lot's review throwaway. A record that cannot be written, or a lot store that cannot be read, adds `! tests.json not written: <reason>` to the gate's lines (a `warnings` field under `gate --json`, with the gate's other not-stored lines), or after the summary of `tdd green` (a `warning` field under `--json`); the run's own record stands.

### Changed

- `lot land` reads the commit lots of the brief through the brief's own reader: a lot without paths, with a glob path or with a blank message, is refused with the reader's reason (`lot land: <brief>: <reason>: nothing pushed`) before anything is pushed.
