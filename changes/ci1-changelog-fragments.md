### Added

- `dialecte changelog check` and `dialecte changelog release <x.y.z> [--date YYYY-MM-DD]`: each lot writes its changelog entry in a fragment `changes/<name>.md` under the changelog's own headings (`### Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`), so two lots never edit the same file. `check` reads every fragment (exit 1 naming the file and the problem: a heading that is no section, text before the first heading, an empty or repeated section, no section). `check` also reads the Unreleased part of `CHANGELOG.md`. `release` writes `## [<x.y.z>] - <date>` (default today, local time) under an emptied `## [Unreleased]` (written above the first version when missing; `## UNRELEASED` is read too), the Unreleased summary and entries first (a section written twice there is merged), then each fragment's in file name order, section by section, one entry per line, and deletes the fragments; code fences and a final link block are kept. Refused, nothing written, when a fragment or the Unreleased part cannot be read, there is no `CHANGELOG.md`, the version is already there or there is nothing to release; a fragment that cannot be deleted afterwards is named, exit 1.
- `dialecte rules`: the `changelog-edit` rule (an error) in a package keeping a `changes/` folder: a change that edits `CHANGELOG.md` without bumping the package version is refused, naming the fragment to write instead (the version is read from the tree the gate checks, in a commit hook the staged one). A package without `changes/` is not judged.
