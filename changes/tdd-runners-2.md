### Changed

- `lot moved` carries a pytest case's red as it does a vitest one: the cli's pytest plugin reports each test module's own code (its module-level statements and those of its test classes, scoped by the class, and each test class's header with its decorators and bases; each import once per binding, by the file or module it resolves to and its names, an import nested in a module-level `try` or `if` by its target too, never importing a module the run did not; never a function pytest collected as a test (a fixture named `test_*` is own code), nor a leading docstring; compared through the syntax tree, so formatting and comments do not count), a red run records it, and a moved pytest case carries its red only when its new file's own code is a subset of the earlier file's at the red, or of the new file's own at the base (the run hands the plugin the base texts of its changed pytest files). The refusal of every moved pytest case is gone; a move is still refused when the red, or the run, recorded no own code of the file (a red recorded before, a file the run did not report), naming what to do instead.
- A moved pytest case also keeps the conftests it ran under at its red (refused under others), and a pytest case's hash now covers its parametrize settings (names, `ids`, `indirect`, `scope`, a values expression), its literal rows aside: changing them is an edit of the case.
- After the upgrade, a pytest case's receipts from an earlier cli read as edited (its hash now covers its parametrize settings): prove such cases red again. A base pytest case whose parametrize settings change in the lot (`indirect`, `ids`, `scope`, a values expression), its rows unchanged, is now a case of change and needs its red.
