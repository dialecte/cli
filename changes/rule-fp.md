### Added

- `dialecte rules` has a `class` rule (error): Dialecte code is functional first, so a class passes only when a package entry exports it (a typed public facade: the `exports` map of `package.json`, followed through `export *`, `export * as`, `export { a as b } from`, an imported name exported again and `export default`, type-only exports included; `export *` never carries a default), when it `implements` an interface (a store), or when it is a data-only error: it extends `Error`, a base named `*Error` or such an error of the same file, and holds only fields (none holding a function), index signatures and a constructor made of `super(…)`, locals and `this.<field> = …` with no function as the value. All of it is inferred from the code, no config. Any other class is an error naming the class and the ways to pass; it is kept only with `// dialecte-allow class: <why>`, on the line before the class or in the comments right before it, its doc comment included. Like the other quality rules, in a run with a gate base an error on a line the change does not add is a warning.

### Changed

- `argument-mutation` also refuses writes through `this` (`this.x = …`, `this.x ??= …`, `this.items.push(…)`, `delete this.x`, `this.n++`, `Object.assign(this, …)`) in a class the `class` rule does not admit, an opted-out class included: one finding per member and written expression, named `<Class>.<member>`. The constructor's own statements, field initializers and static blocks build the instance and are not judged, but an arrow the constructor or a field initializer creates is; an opt-out before a member (decorators included) covers its writes; `this` inside a nested `function`, an object literal's method or a nested class is not the instance's. An admitted facade, store or data-only error keeps its writes. Read on the syntax tree, it does not see a destructuring write (`[this.x] = …`) nor an alias of `this` (`const self = this`).
