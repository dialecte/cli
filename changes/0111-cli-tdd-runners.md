### Added

- `dialecte tdd red` / `tdd green` and the gate's tdd step run and judge `node --test` test files like vitest ones, with the same receipts, ledger entries and red/green proof. The runner of each test file is inferred from the file, no setting: a JS/TS test file importing `node:test` runs under node (even inside a vitest package), a file a vitest config holds under vitest. Node's cases are read through the cli's own node reporter: their names join the describe titles with `>`, `tdd red <file>::<case>` runs that case alone (`--test-name-pattern`), an error inside a `node:assert` call (`assert.equal(...)`, `t.assert.equal(...)`, named imports from `node:assert/strict`) counts as inside an assertion, an import failure or a throwing `describe` refuses the file with its error, and a node timeout is a timeout. Node has no collect-only mode: the gate's tdd step runs a listed node test file in full.
- The same for pytest test files: a Python file is a test file when pytest's own discovery would collect it, read from its pytest folder (the nearest `pytest.toml`, `pytest.ini`, `pyproject.toml` `[tool.pytest]` / `[tool.pytest.ini_options]`, `tox.ini [pytest]` or `setup.cfg [tool:pytest]`, else the package root): its `python_files`, `testpaths` and `norecursedirs`, pytest's defaults when not declared; a file a conftest's `collect_ignore`, `collect_ignore_glob` or `pytest_ignore_collect` leaves out is `outside`, never refused nor frozen. Each file runs in its pytest folder with its interpreter (a `.venv` up to the repository root, else `uv run --frozen python` beside a `uv.lock`, else `python3`; `.venv\Scripts\python.exe` or `python` on Windows), through a pytest plugin the cli ships. A case's name joins its class and function with `>`, parameter ids kept (`TestRows > test_row[2]`); a row added to a parametrize table is a change of that row only, and the case's other decorators must stay as the base holds them, in order and count; `NotImplementedError` is the stub; an `assert` statement or the body of `with pytest.raises(...)` / `pytest.warns(...)` is inside an assertion; `pytest.raises` / `pytest.warns` misses are assertions; an `ImportError: cannot import name` or a missing attribute of the package's own module is a missing export; the conftest files, the helpers a test or a conftest imports and the files a case opens are frozen on red, production never. A run writes no `__pycache__` or `.pytest_cache`; xdist is turned off for the run. A pytest case moved to another file is a new case.
- CI installs pytest 9.0.2 and pytest-xdist 3.8.0 (Python 3.12) so the pytest cases run on every shard.
- The base as round 0: `tdd red` runs a passing case a `revised` entry names, when it is not provably a case of the base or is still waiting for its green with its own test call changed since its red, once more on the base: its file, filtered to the case, under the same runner, in a throwaway copy of the base's tree in the temporary folder with the lot's current test code laid over it (production stays the base's; the copy has a `node_modules` folder of its own linking the package's entries, so Vite's cacheDir lands in the copy). A pytest file runs there with the lot's own interpreter (resolved from the lot's folder), the copy's folder put first on `sys.path` (the current folder dropped) before pytest is imported, whatever the python's version. Red there for a real reason records a red flagged `red on base` (new flag in `tdd status`, the hand-over card and the tdd legend) at the base's production hash, its file frozen; `tdd green` proves it as any red. Otherwise it is refused, nothing frozen: `passes on the base too: the revision proves nothing; prove it red or accept it: lot accept <case> <reason>`, `the base copy lacks a git-ignored input, not a proof` (a missing file or path), `the package is installed editable: a base run would import the lot's code` (pytest), or the failure kind's reason. The lot's tree is never touched; the next `tdd red` / `tdd green` trashes the throwaway folders a killed run left (their owner process gone).

### Changed

- The `outside` line of `tdd` and the gate names every runner: `not a test file of a known runner (no vitest config includes it, no node:test import)`.
- `tdd red` given only `<file>::<case>` targets runs only those cases, vitest included (the other cases of the file are not judged).
- The gate's tdd step no longer skips a package without vitest when the change touches a test file of another runner, edits test code beside node or pytest test files, or deletes a node or pytest test file.
- A failure whose message is empty shows its error's name (`not-implemented: NotImplementedError`).
- One progress step per runner (`tdd red: vitest`, `tdd red: node --test`, `tdd red: pytest`); a run with no test file announces none.
- A revised case that passes now and is not of the base used to be refused (`not provably a case of the base: accept it or prove it red`), as was a revised case whose test changed since its red and that passes; vitest lots included, it now gets a base run (above) and a red on base, or a refusal naming why. Every `tdd` vitest run passes `--cache=false`.
