### Added

- `dialecte lot review <id> [--no-open]`: the private half of a lot's review, printed locally and never sent: the lot's state and branch, its pull request with the head it is at beside the head the lot landed and the worktree's HEAD, its checks, the brief's goal and steps (title, spec, behaviours), the tests record, `decisions.md`, every finding with its text and state, the standard line, and what `lot approve` would refuse (or the command when it would approve). It then opens the pull request's changed files in the browser (`--no-open` names the page only). A lot without a landing prints its private half and names `lot land <id> --draft`. It writes nothing.
- `dialecte lot review <id> --pull --round <n>`: the pull request's line comments come back as findings of round n in the lot's findings ledger: a thread's first comment only, each comment once (`pulled-comments.jsonl`; a second pull answers `already`), its severity from a leading `blocking:`, `should-fix:` or `nit:`, else should-fix, at its `path:line`. `review.jsonl` is written again.
- `dialecte lot approve <id> --by <who> [--reason <text>]`: a person's approval. Refused, nothing recorded and nothing queued, unless the pull request is open at the head the lot landed, its checks are green on that head (a failing or pending check, or none yet, refuses) and no blocking finding is open (open, or a fix still to verify). Then it appends the approval to `approvals.jsonl`, which `review.jsonl` shows as a person's `approve` verdict (the body names it by kind only), renders the pull request's text again and queues it, a draft made ready first. `--by orchestrator` approves the cli's own lots only; every other package waits for a person.
- The host adapter reads the checks on a pull request's head (`gh pr view --json headRefOid,statusCheckRollup`: green, failing, pending or none, never none read as green), its line comments (`gh api .../pulls/<n>/comments`) and opens its changed files in the browser.
