### Changed

- `dialecte changelog release` puts each section's breaking items first: a `- ` bullet opening with a bold `**Breaking` (any case: `**Breaking:**`, `**Breaking (types):**`, `**Breaking** - ...`, `**BREAKING**:`) or the plain `Breaking:` / `Breaking (types):`, the Unreleased ones before the fragments', then every other block in the order written. A list of another kind, a paragraph, a sub-heading, a fence or a column-0 HTML comment is one block, never reordered, and nothing inside a fence (closed only by its own marker, at least as long) or a comment is read as a section heading or an item; a breaking item rises above a sub-heading or paragraph written before it. The section is written as a markdown formatter leaves it: a blank line after an item holding a second paragraph and around any block that is no bullet item, one line feed between one-line items, so oxfmt no longer rewrites a released section. An Unreleased section written twice is merged with a blank line between its parts.
- `dialecte lot brief` changes a lot's commit message (`lots[<n>].message`), which titles its pull request; a lot's paths and the number of lots stay as started, refused naming `lots[<n>].paths` or `lots`.
- **Breaking:** `dialecte lot pr`, `lot land` and `lot approve` refuse a lot that changes package.json's version while its title does not name the new version, naming the `lot brief` command that corrects it; `lot land` pushes nothing and `lot approve` queues nothing. The version is read at the lot's own fork point, so a lot started on an open release lot sets none of its own. A base that cannot be read here (fetch it), a lot read against a base it shares no commit with, a damaged `stack.json` or a stack parent whose records do not read is now refused there too, never read as a lot not stacked; the tdd step of the gate refuses a damaged `stack.json` as `dialecte tdd` does.
