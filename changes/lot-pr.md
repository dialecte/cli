### Added

- `dialecte lot pr <id> [--print] [--json]`: the lot's pull request rendered from its records through the repository's one template, `.github/pull_request_template.md`. The squash commit takes this title and body, so they hold the lot's final state, never its commit bodies. The title is the brief's first commit message; the body holds the brief's `summary` and its other commit messages, each step's title and behaviours, the changelog fragments the lot adds (or its no-entry note's reason), `tests.json` (a part taken on another tree than the committed head reads `stale`, never its counts), `review.jsonl` (each finding's id, round, severity, file and how it closed, then each verdict), the risk class and effort, and `Closes #<issue>`. A record missing reads `not recorded`. The brief's goal, plan and step specs, the gate lines, standard notes and finding text are never rendered. The author's checklist is ticked from the records (tests, changelog, docs step, version bump); everything after the template's kept marker (the reviewer's checklist) is kept from the current body when it is rendered again. The open pull request is edited only when its title or body reads otherwise (`pull request #<n> updated from the lot records`); `--print` sends nothing; without a pull request the text is printed and `lot land <id> --draft` named; a merged or closed one is refused.
- The body's free text (messages, summary, step titles, behaviours, changelog lines) is checked before anything is sent: a reference of the lists (ticket, citation, declared pattern, consumer name, forbidden word), an entry id of the plans that hold the lot, a link, or a path git does not list in the lot's tree or at its base is refused, naming the label, the word and the record to rewrite (`lot pr: the pull request text holds a <label> \`<word>\` in <record>: rewrite that record, nothing sent`).
- The host adapter reads a pull request's body and edits its title and body together (`gh pr edit <n> --title <title> --body-file -`).

### Changed

- `.github/pull_request_template.md` holds the renderer's markers (`<!-- dialecte:<part> -->`, then `<!-- dialecte:kept -->` above the reviewer's checklist); a repository whose template lacks one is refused (`<template> is not the renderer's template (missing marker <part>)`).
