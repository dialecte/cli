## [Unreleased]

### Fixed

- `dialecte lot close` no longer deletes what is only in a hand-over's worktree. It now keeps the worktree, with the reason, when the worktree holds ignored files its removal would delete and nothing else holds (`ignored files git worktree remove would delete: .env`; rebuilt folders, the `.dialecte/lot` link, an empty or archived `.dialecte/lot.json` and files byte-equal, mode included, to the main checkout's still go), when its HEAD reflog reaches commits that neither the hand-over's branch, the base branch nor a remote-tracking ref holds (`its HEAD reflog reaches 1 commit(s) that neither feat/x, main nor a remote-tracking ref holds: ...`; a commit made on a detached HEAD), when a link from outside it points into it (a sibling's `node_modules/@dialecte/core` included), and when another hand-over of the same worktree is neither committed nor abandoned.
- `dialecte lot close` deletes a closed worktree with `git worktree remove` without `--force`: a worktree written into after the check is refused by git and stays in `.worktrees/_trash/`, said in one line when something closed. The `node_modules` caches go to their own `_trash/` entries.
- Paths are compared by their real path as spelled on disk: a hand-over registered with its worktree path in another letter case (a case-insensitive volume) is found and closed.

### Added

- `dialecte.rebuiltIgnored` in `package.json`: ignored folders (`coverage/`), relative to the package root of the main checkout, that `lot close` may delete with a worktree. An invalid entry is ignored.
- `dialecte plan next <plan.md> [--json] [--all]`, in a new `Plan` family of the help: reads a plan's lot block (a fenced `json dialecte-lots` block, or `<plan>.lots.json` beside it) and proposes what can start now, writing nothing. Each entry's state is read from the stores, the hand-over registries and the worktrees (files only); the answer lists the open lots, the lots that can start in critical-path order (with `merge:`, `after`, `unverified`, `stacks:` and the next command), the ones held by an open lot with each scope pair met, the spec work, what each entry waits for, and the machine's heavy steps, load and memory (advice only). Exit 0 when a lot or fix can start, 1 when none can, 2 for a usage error, an invalid block or a repository that is not a git checkout. `dialecte plan check <plan.md>` checks the block alone, every fault at once; `dialecte plan mark <plan.md> <id> done --by <who>` records a person entry's mark in the machine's state folder.

## [0.4.0] - 2026-11-09

### Changed

- **Breaking**: the review rounds' commands move under `lot`, with the same arguments: `record review` is now `lot finding`, `record decision` is now `lot decide`, `record snapshot` is now `lot snapshot`, `record choice` is now `lot choice`, `record standard` is now `lot standard`, `review delta` is now `lot delta`, and `recap` is now `lot recap`. What each prints starts with its new name (`lot finding: R1-1 open - ...`), and every hint the cli prints cites the new forms (the card's standard line: `dialecte lot standard <folder> consulted <note>`). The old forms run nothing and write nothing: each answers `renamed: dialecte <old> is now dialecte <new>` on stderr, then the full new command with the same arguments (with none, the new form's usage line), exit 2, until 2.0; `record` or `review` without a verb names every form that replaced it. Asked with `--help`, an old form prints that answer on stdout with the words given before `--help`, exit 0; with `--help --json`, `{ renamed: [{ old, new }] }`.
- **Breaking**: `dialecte <command> --help` (or `-h`, before `--`) prints that command's section only: its summary, usage lines, what they do, the exit codes that differ from the default and one example; nothing runs. `dialecte --help` prints the commands by family (Discover, Use, Grow, Check, Hand over, Workspace, Maintain) under a new title, and `dialecte --help --json` answers `{ commands: [{ name, family, summary, usage, exitCodes, example, notes }] }` in family order; `dialecte <command> --help --json` answers that one command in the same shape. One map declared in the code is the source of all of them.
- `dialecte --help --json` gives each command its `verbs` and `flags`, derived from its usage lines (`[zero-config flags]` expanded; the global `--help` and `-h` left out), and adds `renamed`: every old form with its new one, words after `dialecte` (`{ old: 'record review', new: 'lot finding' }`). `dialecte <command> --help --json` gives its one command `verbs` and `flags` too.
- `dialecte worktree add` names the folder `.worktrees/<index>-<repository>-<branch tail>` (`0171-cli-x`): a 4-digit index (it grows past `9999`), one counter per workspace, so the latest worktree sorts last. The next index is 1 + the highest of the claims in `.worktrees/.index/` (one empty file per index ever taken) and the numbered folders and links of `.worktrees/`; a claim is created only where none exists, so two runs at the same moment, of any repositories, never take the same index, and a number is never taken again once its worktree is removed. Unnumbered folders and the sibling links (`.worktrees/core`) keep their names. Branches are unchanged. `--json` carries `index`.
- `dialecte lot delta --worktree`: the throwaway keeps the lot's index, `.worktrees/<index>-<repository>-<branch tail>-round-<n>`, and takes no claim; from an unnumbered worktree or the main checkout it takes the workspace's next index.
- `dialecte worktree add` takes the new worktree's `node_modules` from the pool when an entry of the repository matches its `package-lock.json` (a rename, no file copied), else copies it as before. The card's `node_modules` row says which and how long (`pooled  _pool-cli-1  0.1 s`, `copy-on-write  46.2 s`), without the count of re-pointed links; `--json` carries `nodeModules: { method, from?, seconds }`.
- `dialecte handover run --rehearse` in a workspace takes the clone's `node_modules` from the pool when one matches (`node_modules: pooled _pool-<repository>-<n>`), parks it back at the end and sends the rehearsal folder to `.worktrees/_trash/` instead of deleting it in the foreground. `--keep`, and a repository whose parent holds no `.worktrees/`, behave as before.
- `dialecte worktree prune` never lists the pool entries nor what is in the trash (a worktree moved there included): one line each, `pool: 2 entries (cli 1, core 1)` and `trash: 3 folders, being deleted or left over`; a `_pool-*` folder without `pool.json` (a park that never finished) is named as left over. It reads untracked files with `--untracked-files=normal`, so `status.showUntrackedFiles=no` no longer makes a worktree with untracked files look clean.
- The hand-over card of a numbered worktree is titled `hand-over: <index> <repository folder> <branch>` (`hand-over: 0171 cli feat/x`); every card's commit section ends with a `worktree` line, relative to the workspace when the worktree is inside it (`.worktrees/0171-cli-x`), else absolute. `--json` carries `index`.
- The hand-over registry entry stores the worktree's `index`; `dialecte handover show`, `run` and `abandon` accept it (`0171`, or unpadded `171`) and take the newest entry of that worktree, ranked by name. An entry name or a path (`./0171`) still wins.
- The review rounds' verbs (`lot finding`, `decide`, `snapshot`, `choice`, `standard`, `delta`, `recap`) take `<id|folder>`: an id (an index, a full name, a lot folder or `.dialecte/lot`) resolves to its lot folder; a word that is no id, names no lot, or names an existing folder stays a folder as before (with a note when a lot of that id exists). A writing verb refuses an index that several stores hold (exit 2, listing them).
- The folder rule of the review rounds accepts a lot folder (a direct child of `dialecte-lots` in a git common folder, holding the `identity.json` that names it), decided without running git; every other folder in a repository is refused as before.
- `dialecte gate --full` and `dialecte contrib` run a `type-narrowing` step (`npm run type-narrowing`) after the package's own steps (in contrib, before `release`) when the package has that script and none of its steps runs it already: a check a publish workflow runs is now run locally. A package without the script gets one line, `skip  type-narrowing  no npm script "type-narrowing"`, and no step: its records, `--json` rows and hand-over card stay as they were. For a package with the script, the first `gate --full` and `contrib` after the upgrade run again (their command changed).
- `dialecte tdd`, the gate's `tdd` step and the hand-over card treat a test-code file moved with its bytes as at the base (git's R100: a deleted path and a new one, added or untracked, holding the same blob) as no change: a moved test file's cases are listed `unchanged` with no receipt to hold, its old path lists no deleted case, and a moved helper or fixture waits for no freeze. A move stays within one kind (a test file to a test file, other test code to other test code; an empty file never pairs): a rename that turns a test file off (`a.test.ts` to `a.test.ts.off`) lists its cases deleted, one that turns it on is a new file whose cases need red and green. A move with an edit keeps the rule of a new file and a deleted one.
- The gate's `tdd` step lists the cases of a change that only deletes test files as `deleted`, instead of passing with "no test code new or changed since the base".
- `dialecte lot close` keeps a hand-over's worktree when it runs from inside it (`lot close runs from inside <worktree>: run it from another folder, such as cd <main checkout>`) instead of naming its own process as one working there.
- `dialecte handover write <lots.json> --out <id|folder>`: a lot (its index, full name, a path to its folder or `.dialecte/lot`) writes into the lot folder; any other word is a folder as before. The folder is taken by its real path (a folder not made yet: the real path of its nearest existing ancestor, then the rest) before anything is written, so `commit.sh`, the lock, the card, `--json`'s `folder` and the registry all hold it; the default folder (the lots file's) is taken by its real path too. A word naming both an existing folder and a lot is the folder, said by a first line of the output (`outNote` in `--json`). Refused with exit 2, nothing written, in this order: a simulated lot, a `canceled` or `failed` lot, a lot with an open question (`answer q<k> first: dialecte lot answer <full name> q<k> "<answer>" ...`), a lots file whose repository is not the lot's worktree or whose branch is not the lot's (both named); and, for any folder, one whose registered hand-over is `committed` (`<name> is committed: a committed hand-over is never rewritten`).
- `dialecte handover run` refuses a hand-over in the folder of a `canceled` lot (exit 2 before any guard, naming the lot), however it is named: its folder, its registry name, or no argument.
- `dialecte handover abandon` of a hand-over abandoned already whose registry entry still says `pending` (a run killed between the marker and the record) records it `abandoned` and releases the lock naming it, instead of only saying it is abandoned already; while a run of it is in progress it refuses that repair (exit 2). A hand-over whose worktree is gone is recorded in the store of the checkout it is abandoned from, and the lock in that checkout's git folder is released when it names the hand-over (the removed worktree's own git folder, and its lock, went with it).
- `dialecte worktree prune`, `dialecte lot close` and the overlap check of `lot start` read the hand-over registry once per store instead of once per lot.
- `dialecte handover abandon` refuses a lot folder (exit 2, nothing written): `<full name> is a lot: its hand-over is redone with dialecte handover write --rehash --out <full name>; to end the lot: dialecte lot stop <full name>`.
- The hand-over registry's entries are written whole (a temporary file published once for a new entry, renamed over an existing one), so a reader never sees half an entry (a new entry on a file system without hard links is written exclusively instead); they stay writable, so an older cli can still record a state. A hand-over recorded `committed` is never registered again as `pending`. The findings ledger (`lot finding`, `lot decide`), `decisions.md` (`lot choice`) and `standard.json` (`lot standard`) are written whole the same way.
- `dialecte worktree prune` and `dialecte lot close` keep a worktree that a lot of the repository's store names (by real path) while the lot is not `committed` nor `canceled`, with the reason `lot <full name> <state>` (prune: `<branch>: lot <full name> <state>`), checked before every other keep rule; the store is read once per repository, no git process per lot.
- `dialecte lot recap` on a lot folder renders, after the rows of `decisions.md`, one decision per answer of the lot (`answers/q<k>.json`, in `k` order): `q<k> <question text> -> <answer>`, by who answered, on the UTC day of the answer. Answers are never copied into `decisions.md`; recap still writes nothing.
- The usage errors of `lot finding`, `snapshot`, `choice`, `standard`, `delta` and `recap` name `<id|folder>`; `lot decide`'s names `<id|folder> <finding>`.

### Added

- `dialecte lot start <brief.json> [--effort low|medium|high] [--dry-run] [--json]`: checks the brief (every refusal at once, exit 2, nothing created; a lot path is inside a scope entry by path segments, `lib/x` inside `lib/` and `lib-other/x` not, an entry whose glob cuts a name, `src/data*`, by string prefix), claims the next worktree index, publishes the lot folder in the lot store, makes the numbered worktree at the recorded base commit with its `.dialecte/lot` link, and prints the full name, the folder, the worktree, `runner: manual` and the next command. `--dry-run` checks and names the lot and the start to run next (`next: dialecte lot start <brief path as given>`; the store list refused in a work tree as for a start), writing and claiming nothing. A worktree that cannot be made leaves the lot `failed` (exit 1), nothing removed, and names `next: dialecte lot stop <full name> --reason <text>`; a link that cannot be made leaves the lot working (exit 0, a `note:` line, `notes` in JSON; `lot status` reports the link missing). Every `--json` exit is JSON: `{ dryRun: true, lot, worktree, next }` for a dry run, `{ lot, folder, state, reason, next }` for a failed lot, `{ refused, next: null }` for a refused brief, `{ error, usage, next: null }` for a usage error, `{ error, next: null }` for any other exit before a lot exists. Two overlapping lots started at the same moment never both go on.
- `dialecte lot start --simulate <scenario>`: a simulated lot playing one of the scenarios (`ready`, `question`, `person`, `two-questions`, `limit`, `failure`, `slow`) under `lot wait`, publishing the records a real run would; it writes only its lot folder, one store-list line and one index claim (no branch, worktree or registry entry), never blocks a real lot, and names `next: dialecte lot wait <full name> --timeout 60`. Every brief check still runs; an overlap or an existing branch is recorded in `wouldRefuse` instead of refusing. `--simulate <scenario> --dry-run` is the dry run of the simulated start: exit 0, the findings listed (`{ dryRun: true, lot, worktree: null, wouldRefuse, next }` in JSON), never "every check passed" over them, no worktree named, `next` the same start with `--simulate <scenario>`; nothing claimed or written. An unknown scenario exits 2 naming every scenario.
- `dialecte lot wait <id> [--timeout <seconds>] [--json]`: the status as soon as the lot needs someone, with the exit codes 0 (`ready`, `committed`), 1 (`failed`, `canceled`), 3 (`input-required`, at once), 4 (the last transition is a limit: run again) and 5 (`--timeout` reached, still working). A real lot is looked at every second by a stat of its folders and the registry, read again only when one changed, nothing written; a refreshing `waiting <name> (<state>, <elapsed>)` line on a terminal, none under `--json`. A simulated lot is played up to its next blocking point; two waits on one lot play each step once.
- `dialecte lot answer <id> <question> "<answer>" [--by <who>] [--json]`: records the answer to an open question once (the same answer again is `already`, another refused), checks it against the question's options, requires `--by <who>` for a person's question, runs the answer hooks, and prints the status with `next: dialecte lot wait <full name>`. A refusal exits 2, a hook that throws exits 1 with the answer kept.
- `dialecte lot result <id> [--json]`: never blocks, writes nothing. `ready` or `committed` exits 0 with the hand-over (`name`, `folder`, its own `state` from git, the `card` of `handover show --json`, the `show` and `run` lines), the worktree, the branch and the answered questions; a simulated lot's hand-over is `{ simulated: true }`. `failed` and `canceled` exit 1 with `{ state, reason, at, position }`, `input-required` exits 3 with the open questions, `working` exits 5.
- `dialecte lot stop <id> --reason <text> [--by <who>] [--json]`: ends a lot. A pending hand-over is abandoned first (the logic of `handover abandon`, now one library function both run); a run in progress or a hand-over committed meanwhile refuses the stop (exit 2, nothing published). Then a `canceled` transition with the reason and who stopped it (`caller` by default), and the registry read once more so a hand-over registered meanwhile is abandoned at once. A lot already canceled exits 0 writing nothing; one left with a `pending` entry is repaired. `committed` exits 2. It moves no worktree and deletes nothing. The `next` of a failed lot (`dialecte lot stop <full name> --reason <text>`) and of a ready lot without a hand-over (`dialecte lot result <full name>`) now run.
- `dialecte inbox [--repository <name>] [--simulated] [--json]`, in the Grow family: what waits on someone across every store of the store list and the store of the current folder, one line per open question (person, then caller), then the ready and the failed lots, by index within a group, each with its exact next command; then `working <n> · simulated <m> (listed with --simulated)`. `--repository` keeps one repository folder by name; `--simulated` lists the simulated lots that wait; a lot folder whose identity does not read, or whose records do not hold, is a `damaged <folder>: <reason>` line. A lot's records are checked once, on read (a question id `q<k>` with k 1 or more, an audience `caller` or `person`, a position's step, of and round non-negative integers, a transition's `at` a time, an answer file's question its file's `q<k>`): a lot that fails reads damaged, every lot verb refuses it (exit 2), and no forged field reaches a line or a `next`. Reads files only, each registry once per store, runs no process. `--json`: `{ waiting, working, simulated, damaged }`, `waiting` the status of each waiting lot. Exit 0 when something waits or is damaged, else 1; 2 for a usage error.
- Agent text the lot verbs print in their text form (`status`, `wait`, `answer`, `result`, `stop`, `inbox`: question texts, stations, options, recorded answers, who answered, reasons, notes) shows control characters, bidi overrides and isolates, bidi marks and line separators as `\u{<hex>}`; each field is escaped whole before it joins a line, so a line feed in it prints as `\u{a}` and never adds a line of its own; `--json` carries the text as stored. A question raised with a station or an option holding a line break (LF, CRLF, lone CR) is refused, as a multi-line question text already was, nothing published.
- Every answer of `lot status`, `wait`, `answer`, `result` and `stop` prints on standard output whatever its exit code (0, 1, 3, 4, 5); only a usage error or a refusal (exit 2), and an answer hook that threw (exit 1 of `answer`), print on standard error; `inbox` follows the same rule. `lot start` stays outside it: a refused start (exit 2) or a failed one (exit 1, the lot `failed`) is an error on standard error, naming the lot and its next command. A refusal of `lot answer` escapes the options, answer and `--by` it quotes and stays one line. The answer line a `next` names for a caller's question carries no `--by` (it defaults to `caller`); a person's keeps `--by <who>`. A simulated lot's `lot status` carries its start's findings in `checks.wouldRefuse`.
- `dialecte lot status <id> [--json]`: the lot's state derived from its records (`working`, `input-required`, `ready`, `committed`, `canceled`, `failed`), its position, open questions, hand-over, worktree and link checks, and the exact next command (the text form may add an `also:` line); reads files only, runs no process, writes nothing. Exit 2 for an unknown or ambiguous id (`{ error, next: null }` with `--json`) or a usage error (`{ error, usage, next: null }`).
- The lot store, `<git common folder>/dialecte-lots/`: one folder per lot (`brief.json`, `plan.md`, `identity.json`, `transitions/`, `answers/`), each record published whole and once, read-only; a lot folder is built aside and renamed into place, and the leftovers of a writer that died are removed by the next one.
- The user's store list, `$XDG_STATE_HOME/dialecte/lot-stores` (else `~/.local/state/dialecte/lot-stores`): one store per line, appended by `lot start`, read by ids to see every store of the machine; refused when it would sit inside a git work tree.
- `dialecte standard index | find | show | eval`, in the Discover family: the index of the standards kept on the machine, outside every repository. `DIALECTE_STANDARD` names a root folder holding one folder per standard (its lowercased name is the standard's id; its top-level `.md` files are the standard, a file's id `<standard id>/<name>`). The index of each standard lives in the cache only, `$XDG_CACHE_HOME/dialecte/standard/<id>/<manifest hash>/` (else `~/.cache/dialecte/`; the manifest hash holds the index format, 2, so a folder of an earlier format is never reused), built into a temporary folder and renamed into place, reused while the files are unchanged (`--rebuild` forces a build), aborted when a file changes during the build; the links to the vocabulary are a file of their own, named by the selected dialectes' `name@version` list and added when it changes. The vocabulary is the tags, attributes and enumeration values of the dialectes installed where the command runs, or of the one `--package <name>` names on `index`, `find` and `eval` (not installed: exit 2 naming the installed ones): exact names, case kept, never stemmed, scored like a word (no link strength, weighted by the lines naming it); a name in lowercase letters only, from three characters, is searched as a word. Those three verbs print `vocabulary <name@version>[, ...]` (or `vocabulary none (no dialecte installed)`) first, and `vocabulary: { packages }` in `--json`. Other words are searched by their stem (plural, `-ied`, `-ying`, `-ing`, `-ed` and a final `e` removed), common, modal and question words left out; an acronym (capitals and digits, two capitals or more) is kept from two characters, never split nor stemmed, its plural with one lowercase `s` searched as the acronym. A slice starts at the first hit of its unit's densest window (at most 60 lines holding the largest weight of distinct terms; a table at its caption when that window ends within 60 lines of it) and runs to the unit's last hit, capped at 60 lines; the unit's score is unchanged. `index` prints each file's quality (verdict, noise, headings, tables, definitions, repeated lines); `find "<terms>" [--about <Tag>] [--limit <n>]` the ranked slices of whole lines with their original line numbers, then the clauses they refer to `[linked]`; `show <file id>:<from>-<to>` the normalised text of a range; `eval <gold.jsonl>` the recall at 5 and 10 of `find` over a local gold file (an item's expected quotes are alternatives, matched in plain words without their markdown markup), with the reason of each miss. `--standard <id>` picks one standard. Refused with exit 2: no root configured, a root that is a file, holds `.md` files directly or holds no standard folder, colliding ids, an unknown standard or file, a root, standard folder or cache inside a git work tree. A `--rebuild` puts the new folder in place before the old one is removed, so a reader never sees a half-removed index.
- `dialecte skills check` verifies every cli invocation a skill page cites in code (inline code and fenced blocks of any language, generated blocks left out) against the command map of the cli the package uses: the cli's own map in the cli itself, else the installed `@dialecte/cli`'s `dialecte --help --json`. An unknown command, verb or flag, or an old renamed form (`dialecte record review`, `dialecte review delta`, `dialecte recap`), is an error printed as `page:line`, naming the closest valid form (`dialecte lot finding`) or, with none close, the valid verbs or flags. `<!-- dialecte-skills ignore: ... -->` skips the finding whose word it names. With no installed cli, or one before the map, the invocations are not checked and one warning says why; the exit code does not change for it.
- `dialecte handover write <lots.json>` writes the hand-over `dialecte handover <lots.json>` writes, which stays; `handover` alone names its verbs.
- The `node_modules` pool: `.worktrees/_pool-<repository>-<n>/node_modules` with a `pool.json` (`{ repository, lockHash, parkedAt }`, `lockHash` the sha256 of `package-lock.json`), at most two entries per repository. A park takes only a `node_modules` that matches its `package-lock.json`, rewrites absolute in place the links leaving it by a relative path, renames the folder in, sends `.vite` and `.cache` to the trash, then writes `pool.json`; a take renames the newest matching entry out. Used only where the repository's parent holds `.worktrees/`.
- The trash, `.worktrees/_trash/`: a worktree is moved there by `git worktree move` and removed by a background `git worktree remove --force`, a folder renamed there and removed by a background `rm -rf`; nothing waits for them, a folder left over stays to look at.
- `dialecte lot close <hand-over name|index>... [--json]`: for each committed or abandoned hand-over of the registry named, its worktree (the path the registry entry holds) sent to the trash, then its `node_modules` parked in the pool from there; the branch never touched. Kept with why, nothing done: a pending hand-over, the main checkout, no registered worktree at that path (or one in the trash or the pool), a worktree on another branch than the hand-over's (both named), a locked worktree, a mutation run from it, a process working in it, the processes not known (`lsof` failed or timed out), a dirty worktree. Each line names the folder it moved and where `node_modules` went (`pooled in <entry>` or `trashed: <why>`). Exit 0 all closed, 1 one kept, 2 a name or index the registry does not hold.
- Scoped gate steps and `dialecte gate --release`. A gate step may say `"scoped": true`: it gets `DIALECTE_GATE_BASE` and `DIALECTE_GATE_TREE` (the base and tree the gate resolved once), `DIALECTE_GATE_CHANGED` (the changed paths, NUL-separated) and `DIALECTE_GATE_SELECTION` (where it writes its selection JSON `{ schema: 1, base, tree, changed, selected: [{ id, reasons }], skipped: [{ id, reason }] }`), and is judged on that selection; the base is `--base <ref>`, else the merge-base with `dialecte.baseBranch` (default `main`), else the empty tree, and enters the record's key. `"heavy": true` marks a heavy suite (outside the command hash). `dialecte gate --release` (alone) runs `dialecte.gate.release` (default: the `--full` steps) with every scoped step against the empty tree and records `dialecte-gate-release.json`; a green release record of a list that covers full answers a commit hook, a rehearsal's lots, contrib's steps and the card. `gate --hook` on a scoped package prints `gate --hook: base <sha> (<source>), selected <ids>|nothing selected|reused`, and `handover run` hands its hooks the hand-over base (`DIALECTE_HANDOVER_BASE`, `DIALECTE_HANDOVER_FOLDER`); hook records are keyed with the base the hook printed. The card says what a scoped step selected since its base, reads a record of an older base as current (`(older base)`) and one whose base moved as stale, and prints `✗ gate  invalid gate config: <message>`; `handover write --release` marks a release hand-over (`"release": true`), whose card requires a `gate release` row. An invalid gate config exits 2 (`gate`, `contrib`, `handover run`, nothing staged) or 1 (`gate --hook`). A package without a scoped step keeps its command and hook hashes; every failed or flaky step now records its failing files and the card's row of a failed step shows them; the hook's running line now says `no green gate --full or --release`.
- A failed gate step records the files its whole output names as failing, with those a scoped step's selection declares (`"failing": [...]`, paths relative to the package root), sorted and unique: `failing` on the record's step and in `gate --json`, and the card's row of a failed step ends `· failing <n>: <first 3>[, +<k> more]`. ## [0.2.0] - 2026-11-03

### Added

- `dialecte mutants run | status | schedule | abandon | migrate`: mutation testing of the scope a package declares in `package.json` (`"dialecte": { "mutation" }`). `run` mutates the scope lines changed since the merge base with the base branch (else the remote's default branch, else it refuses with exit 2; `--base <ref>` for another one), or the whole scope with `--mode audit`; without `--mode` it follows the lot's switch. The run is written `running` (process id, worktree, branch, lot, tree, mode, base) to `<git-common-dir>/dialecte-mutation/runs/` before Stryker starts and replaced `reported` with its counts and survivors when it ends, so a run killed mid-way reads `died` from any worktree of the repository. Tiers in order: fast, the timed-out mutants alone, the declared full tier on the survivors no committed record lists. Survivors no record lists enter the ledger `<git-common-dir>/dialecte-mutation/ledger.json` as `new` and stay there until a later run detects that exact mutant (`killed`; never a run that started before the last run reporting it), a record explains them (`recorded`), or `schedule <follow-up>` moves them to `scheduled`; a survivor whose line changed or went away stays pending. The last lines name the package, lot, tree, mode, counts, each new survivor and each ledger item the run moved to `killed` or `recorded`; survivors never fail the command, a failing Stryker exits 1. `status [--json]` lists running runs with their age, died runs, new survivors by lot and scheduled ones by follow-up; `abandon <run id>` marks a died run abandoned and keeps it; `migrate` turns `scripts/mutants/equivalent-mutants.json` into `.dialecte/mutation-records.json`. A run records its owner process's start time too (a pid now held by a process that started at another time reads `died`), names an empty Stryker config file so a package's own `stryker.config.json` is never merged in, refuses a detached HEAD, and removes its work folder (`.tmp/mutants/<run id>/`) once reported. The ledger's readers and writers hold a lock file (a lock whose owner process is gone, or that names no owner and is a few seconds old, is taken over) and first take in, in the order they started, any reported run whose ledger update was missed; a scheduled survivor follows the same rules and keeps its follow-up. Stryker's incremental file is kept per package and key in `<git-common-dir>/dialecte-mutation/incremental/` (seeded into the run's work folder, written back after a reported fast tier; the key holds the whole tree, the lock, the linked dependencies, the fast options, the cli version and the ignorer's bytes), so it is reused on an identical tree only and never across edits; the newest 4 files of a package are kept, and a failed write-back only prints a warning. The build ships the ignore rules Stryker loads as `dist/ignorers.js`.
- `dialecte mutants judge | record | drop`, and `--json` on every `mutants` verb but `run`. `judge [--file <file>]` prints the package's new survivors as capped per-file packets (10 survivors, 12000 bytes of JSON and of text each): per survivor a family guess with its reason, the covering tests the last run named (a run entry's survivors now carry the first five covering test names, sorted, and how many more), the code around it as it is now with the mutated lines marked and a flag when its line changed since the run, and the `record` / `schedule` commands. `record (--key <key>... | --file <file>) --family <family> --reason <text> [--removable]` writes the records to `.dialecte/mutation-records.json`, then moves the new or scheduled survivors to `recorded`, under the ledger lock and records first (`unclassified`, an unknown family or key, an empty or over-200-character reason refuse the call and write nothing). `drop <run id>` removes an abandoned run, or a reported run, from the store; it refuses a running or died run and the latest reported run of its branch (it is that branch's evidence: drop it once a newer run of the branch reported). With `--json` a verb prints exactly one JSON object on stdout, `{ "verb", "ok", ... }` or `{ "verb", "ok": false, "reason" }`, whatever its exit code.
- Pending mutation work now blocks the hand-over. The `dialecte handover` card gets a `mutation` line (after `rules`, for a package that declares a mutation scope): `✗` and BLOCKED on `new` survivors or died runs of the package (`2 new survivors · 1 died run: dialecte mutants status`), on a run still running that a merge hand-over or a `gate` lot waits for, and on a `gate` lot with no run of its branch reported on the tree it commits (`gate lot: run dialecte mutants run on this tree first`); `!` for a run of the branch still running on a plain hand-over (`its survivors are not in yet`); else `✓ nothing pending`. `handover run` checks the same thing again as its last guard, `mutation`, when it runs: a survivor reported or a run that died after the card was written refuses the run (exit 1, nothing committed), each survivor and died run listed with what to do (a test that kills it, `dialecte mutants record --key <key> --family <family> --reason <why>`, `dialecte mutants schedule`, or rerun / `dialecte mutants abandon`). `dialecte recap` gets a `Mutation` section: the runs of the lot's branches with their counts, the survivors they killed or recorded, the lot's scheduled survivors. `dialecte worktree prune` keeps a worktree a mutation run was started from while the run runs or after it died unreported.

### Fixed

- The `typescript` peer range is `>=5.4 <7`: npm installed TypeScript 7 (the native port, no compiler API) beside the cli, and every `dialecte` command crashed at startup.
- `npm run build` always holds the tdd reporter: tsup built its three configs at once and the first one's `clean` could delete `tdd-reporter.js` the third had already written (seen under load, every `dialecte tdd` from that `dist/` then failed). The suite no longer rebuilds the checkout's `dist/` (its build test writes into a folder of its own), so a suite run never breaks the `dialecte` other sessions run from that checkout.

A line a step prints several times (Vite's `configLoader` notice, 2-3 times per build) is not repeated: on a terminal it is one line whose count, `(×3)`, updates in place; off a terminal (a log) it is written as it is read, its identical repeats right after it are counted, and when that run of repeats ends (another warning or error line, the next step, the hook's end) a run of two or more is written again with its count (`W`, `W (×2)`, `W2`, `W` for W W W2 W); after the hook it is listed once, where it was first printed, with its step's total. Lines of different steps never merge. Before any commit staging a changed `package-lock.json`, `node_modules` are brought to it: `npm ci` on the staged lock and `package.json` (the working copies saved in `dialecte-install-backup` in the git folder and put back after, on an interrupt too; a backup a crash left is restored by the next run, or refused when the files changed since). Merge lots need git 2.38 or later; `merges.json` is under the review hash; a `null` resolution removes the file; a conflicted symlink or submodule, and a working-tree change of a file the merge changes, are refused at the write; a merge of the lot's tip left in progress is redone only when this cli started it, or with `--resume-merge`. The card counts the tdd flags per kind (`dialecte tdd status --flags` lists them); a stopped run prints the card too.
- A running step looks running: `gate` steps, `tdd`'s vitest run, `handover run`'s lots and its rehearsal clone print a start line `▶ <step>` before any work off a terminal (and a line every 30 s of silence), and on a terminal one spinner line `⠋ <step> - <what runs> <elapsed>` that the step's result line replaces; the last visible line is never a ✓ while work continues. A hook's output is never buffered: its full log is written as it runs. On a terminal the live region is the plain text of each line (colours and control sequences removed, tabs expanded) fitted to the width by the cells it takes, never taller than the screen less one row, read again at each redraw; an interrupt or an exit leaves it on its own line. A silent hook gets the waiting-for-input / watch-mode hint once at 90 s, on a terminal and off it. `gate` on a terminal announces its tdd step too, shows each step line once in run order, and its summary leaves out the lines already shown. The hand-over card prints the command whole under the box: `node <this cli> handover run <folder>` when the repository's own cli does not answer `handover run --probe` within 10 s. `handover run --rehearse` warns, naming at most 10 of them (a wholly untracked folder as one entry), about untracked files outside `.gitignore` and `.git/info/exclude` a hook could read. `worktree add` lists `.dialecte/` in the exclude file of the repository's common git folder and copies `node_modules` from the worktree that has the `--from` branch checked out, else from the main checkout. `dialecte lot` refuses a lot file that holds no object and a case not written `<file>::<name>`. `dialecte lot exempt <reason>` / `lot accept <case> <reason>` / `lot revised <case> <reason>` write `.dialecte/lot.json` at the package root, tab-indented.
- No silent hang: every child that `dialecte gate` (its steps), `tdd` (its vitest runs) and `handover run` (each commit and its hooks, `--rehearse` too) start runs in a process group of its own, with its stdin closed, under a stall watchdog. Output (a part of a line included) or CPU time gained by its tree (descendants and process group, sampled with `ps` every 5 s, with a timeout) counts as activity; after 10 minutes with neither, the tree is printed (pid, state, CPU time, command), stopped (SIGTERM, SIGKILL after 2 s) and the run ends once its processes are gone, as `stalled`: the gate's step `stalled: no output, no CPU for 10 m 0 s` with the tree in its tail, `tdd`'s run with the tree, a hand-over lot not committed and unstaged (or, when a stopped git's `index.lock` stays, reported as still staged, naming the lock and saying to hand its path to the person who runs the repository). A `ps` failing for the whole 10 minutes is a stall too. Ctrl-C, SIGTERM and SIGHUP are passed on to every running child's group (a rehearsal stops the hook's group before it removes its clone). A child asking the terminal (a gpg or ssh prompt) is in a background group: it stops (state `T`) and is reported as stalled. The gate's steps and `tdd`'s vitest run are no longer synchronous spawns.
- `dialecte tdd red|green|status [<test file> | <test file>::<case name>]... [--json]`: a ledger in the worktree's git folder that makes the order of a lot's work visible. `red` runs every case of the changed test files with the package's own vitest (each project's run a case of its own; snapshots never written): a failure on an assertion, a snapshot mismatch, a stub's `not implemented` or a TypeError of existing code, inside an `expect(...)` a matcher completes, is a red; a passing new or changed case, a case whose test call changed since its receipt, a failure on a missing export, a type or syntax error, a timeout, a stub thrown at import or before the assertion, and a file holding `.only` / `only: true` are refused with their reason; a case the same as at the base is marked unchanged. One refusal records no red of its file; refusals are kept in the ledger. Reds record the hashes of the test file, of the case's own test call and of the production files, and are flagged `rollback` (a production state the case had left) or `red after green`. The run freezes the test files without a refusal and the changed helpers, fixtures and snapshots. `green` refuses test code changed since its freeze ("tests are frozen after red; go back to the test station"), a case without a red receipt, a green with nothing changed in production since its red, and a failure. `status` prints each case with its flags, the test code changed outside `tdd red`, and the cases the change deletes. A ledger that cannot be read is refused with its path.
- `dialecte gate --fast` and `--full` run a `tdd` step after the hygiene: every test-code file changed since the base as the red run that last froze it, every case of the change red then green (or unchanged); the flags and deleted cases printed under the step. A lot declared exempt in `.dialecte/lot.json` (`{ "tdd": "exempt: <reason>" }`, never committed: the hygiene and the hand-over leave the file out, wherever the package sits in its repository) passes with its reason and the count of production and test files the change touches; the hand-over card shows the same and the flags. A package that does not test with vitest skips the step.
- The tdd red run refuses a passing case still waiting for its green whose test file or imported test code changed since its red ("test code changed since its red and it passes"); a green case kept at such a run is recorded and flagged `test code changed around it`. A helper, fixture or snapshot is frozen only by a red of a file depending on it (relative imports followed through test code, a file named in its text, its snapshot). An error any existing code throws inside an asserting `expect` is a red, not only a TypeError. `red after green` flags only a case whose own last receipt is a green at the same production state. `.dialecte/lot.json` may accept cases without a red (`"accept": [{ "case", "reason" }]`), shown with their reason by the gate and the hand-over card. `dialecte new verb` writes its red case without `only`.
- `tdd` measures the lot from HEAD: on a branch holding earlier committed lots, only the uncommitted work is the change. `tdd ... --base <ref>` and `gate --base <ref>` give the whole-branch view (from where HEAD left the ref); `gate --full` measures from where the branch left its base branch (before a merge). Test code is compared by the leaves of the parser's syntax tree (each file parsed by its extension: a `.ts` file is no TSX): whitespace, comments (except `@vitest-environment`, `@jest-environment` and `@vite-ignore` ones), quote style, statement semicolons, trailing commas after an element and the order of import statements between side-effect imports are formatting, not an edit; template literals are compared by their raw text; any other change is. The ledger format is version 3: a version-2 ledger is refused with the advice to move it aside. A repository without a commit is refused in one line. A file with a refused case still records its other cases' receipts (it stays unfrozen); `green` takes a red recorded in a file never frozen as it saw the file. `"dialecte": { "tdd": { "production": ["src/test"] } }` declares folders whose files are production code (a package's test entry), except the test files, fixtures, snapshots and `*.script.ts` under them. `testCase.only ? it.only : it` (a runner picking per row) is no focus marker; a call through `.only` and `only: true` still are. `.dialecte/lot.json` may declare cases revised at review (`"revised": [{ "case", "reason" }]`; the case needs an earlier receipt, not necessarily a red): the next `tdd red` records a passing revised case as `revised` (a failing one is a red) and freezes the file again; status, the gate step and the hand-over card show them with their reason, and an entry no red run used as a note. `handover run --rehearse` removes the folders a deleted file leaves empty in the clone.
- The tdd test dependencies follow imports through the package's tsconfig `paths` and vite `resolve.alias` (barrels and re-exports included); a bare package name is never test code, and an import that looks local and resolves nowhere refuses its file at `tdd red`, naming it. The lot file is strict (unknown keys and an exemption without a reason are refused); the hand-over card lists the accepted receipts of the ledger, marking those whose entry left the lot file, and the gate and the card report an acceptance no case used.

- `dialecte handover run <folder> [--rehearse [--keep]]`: the hand-over runner `commit.sh` calls. Each guard (repository, hooks folder, branch, HEAD, empty index, the snapshot, deleted files, files outside the lots, plan tags and citations in files and messages) prints one line with its result and its time; then `lot n/N` with its files and subject, the commit's hook output with a heartbeat every 30 s while it is silent (after three silent beats, it asks whether the hook waits for input or runs in watch mode), the commit with its stat, the total time and the card.
