## [Unreleased]

### Added

- `dialecte mutants run | status | schedule | abandon | migrate`: mutation testing of the scope a package declares in `package.json` (`"dialecte": { "mutation" }`). `run` mutates the scope lines changed since the merge base with the base branch (else the remote's default branch, else it refuses with exit 2; `--base <ref>` for another one), or the whole scope with `--mode audit`; without `--mode` it follows the lot's switch. The run is written `running` (process id, worktree, branch, lot, tree, mode, base) to `<git-common-dir>/dialecte-mutation/runs/` before Stryker starts and replaced `reported` with its counts and survivors when it ends, so a run killed mid-way reads `died` from any worktree of the repository. Tiers in order: fast, the timed-out mutants alone, the declared full tier on the survivors no committed record lists. Survivors no record lists enter the ledger `<git-common-dir>/dialecte-mutation/ledger.json` as `new` and stay there until a later run detects that exact mutant (`killed`; never a run that started before the last run reporting it), a record explains them (`recorded`), or `schedule <follow-up>` moves them to `scheduled`; a survivor whose line changed or went away stays pending. The last lines name the package, lot, tree, mode, counts, each new survivor and each ledger item the run moved to `killed` or `recorded`; survivors never fail the command, a failing Stryker exits 1. `status [--json]` lists running runs with their age, died runs, new survivors by lot and scheduled ones by follow-up; `abandon <run id>` marks a died run abandoned and keeps it; `migrate` turns `scripts/mutants/equivalent-mutants.json` into `.dialecte/mutation-records.json`. A run records its owner process's start time too (a pid now held by a process that started at another time reads `died`), names an empty Stryker config file so a package's own `stryker.config.json` is never merged in, refuses a detached HEAD, and removes its work folder (`.tmp/mutants/<run id>/`) once reported. The ledger's readers and writers hold a lock file (a lock whose owner process is gone, or that names no owner and is a few seconds old, is taken over) and first take in, in the order they started, any reported run whose ledger update was missed; a scheduled survivor follows the same rules and keeps its follow-up. The build ships the ignore rules Stryker loads as `dist/ignorers.js`.
- Pending mutation work now blocks the hand-over. The `dialecte handover` card gets a `mutation` line (after `rules`, for a package that declares a mutation scope): `✗` and BLOCKED on `new` survivors or died runs of the package (`2 new survivors · 1 died run: dialecte mutants status`), on a run still running that a merge hand-over or a `gate` lot waits for, and on a `gate` lot with no run of its branch reported on the tree it commits (`gate lot: run dialecte mutants run on this tree first`); `!` for a run of the branch still running on a plain hand-over (`its survivors are not in yet`); else `✓ nothing pending`. `handover run` checks the same thing again as its last guard, `mutation`, when it runs: a survivor reported or a run that died after the card was written refuses the run (exit 1, nothing committed), each survivor and died run listed with what to do (a test that kills it, a recorded reason in `.dialecte/mutation-records.json`, `dialecte mutants schedule`, or rerun / `dialecte mutants abandon`). `dialecte recap` gets a `Mutation` section: the runs of the lot's branches with their counts, the survivors they killed or recorded, the lot's scheduled survivors. `dialecte worktree prune` keeps a worktree a mutation run was started from while the run runs or after it died unreported.

### Fixed

- `npm run build` always holds the tdd reporter: tsup built its three configs at once and the first one's `clean` could delete `tdd-reporter.js` the third had already written (seen under load, every `dialecte tdd` from that `dist/` then failed). The config now empties the output folder once, before any build, and no config cleans. The suite no longer rebuilds the checkout's `dist/` (its build test writes into a folder of its own), so a suite run never breaks the `dialecte` other sessions run from that checkout.
- A failing oxfmt says why: the warning `⚠ oxfmt exited <n> — emitted files may be unformatted` is followed, indented under it, by the files it was formatting (ten named, then `and <n> more`) and oxfmt's own stderr lines (stdout when stderr is empty); an oxfmt that cannot start is named with its error (`⚠ oxfmt could not start (<error>) — emitted files left unformatted`).
- `handover run`: the commit hook's warning and error lines are labelled by the step that printed them (`[lint:check] <line>`), live and after the hook, and the summary counts warnings per step and kind (`1 lint warning in lint:check`), each distinct line once (the same text printed again in its step counts once). A line a step prints several times (Vite's `configLoader` notice, 2-3 times per build) is not repeated: on a terminal it is one line whose count, `(×3)`, updates in place; off a terminal (a log) it is written as it is read, its identical repeats right after it are counted, and when that run of repeats ends (another warning or error line, the next step, the hook's end) a run of two or more is written again with its count (`W`, `W (×2)`, `W2`, `W` for W W W2 W); after the hook it is listed once, where it was first printed, with its step's total. Lines of different steps never merge. A test step (a `test` segment in its name, or `vitest`, `jest`, `node --test` on its command line) shows only its failing tests and failed scripts: the warnings a test suite prints (a generator's `⚠ oxfmt exited` in a scratch folder) are no longer counted as the repository's lint warnings.
- `handover run`: the commit hook's result is a gate record (`dialecte-gate-hook.json` in the git folder of the repository it commits in: HEAD after it, the state hash of the tree before the commit, the steps its summary names with their counts), read by the card with the gate records unless a gate record is newer (a gate run replaces the hook's lines whole: the hook names its own scripts, not the gate's steps); its lines end with `commit hook` (`✓ test:run  1214/1214 · commit hook`), and the legend explains the term. A lot committed where no `dialecte gate` ran (a merge in the main checkout) no longer shows `✗ gate  never run on this tree` after a green hook. A failed hook is recorded too; a hook stopped as stalled and a repository without a commit hook record nothing; a rehearsal records in its scratch clone and in the repository's store of records by tree, never in the repository's own `dialecte-gate-hook.json`.
- The hand-over card of a hand-over holding a merge lot checks the tree its last lot leaves (the merge with its resolutions), not the working tree of the branch it merges into: a merge whose tree is its tip's shows the branch commit's hook record as current instead of `(the tree changed since)`. The card's gate lines also read the records of that tree other worktrees and rehearsals stored (their tdd step left out); a stored record counts only when it ran against what is installed here now with the command of its mode now; a line from a record made at a commit outside the history of HEAD ends `· from <sha>` (a record of an earlier commit of this line carries none), a rehearsal's `· rehearsal`.
- `handover run`: the card printed after a real run has no `notes` section: the lots file's `gates` text was written for the person about to run and went stale once the run showed its gates. The written card and a rehearsal's keep it.
- `handover run` brings `node_modules` to a staged lock with `npm ci --ignore-scripts --prefer-offline --no-audit --no-fund`: an install script (the root's `prepare: husky`) no longer runs mid-run and changes git config or hooks. `npm ci` reinstalls every package, so the note after the sync names each installed package of the staged lock that has an install script (`install scripts not run: <names>`, each package once by its name, five named then `and <n> more`); a refusal names the command as run.
- `tdd red` flags `test code changed around it` only on a case proven green: a case of the base never proven (only unchanged, accepted or revised receipts) is kept without a flag and records no receipt when its test file or a helper changes.
- A case declared `revised` is a case of the base, when its own title is the literal title of an `it` / `test` call at the base or now, only through its test call: the base holds a call of that title with its describe path (a computed describe title, a `describe.each` / `describe.for` format, matches any; a `describe.skipIf` / `describe.runIf` suite counts by its title; `it.for`, `it.skipIf`, `it.runIf` are test calls) and the file now holds no more of them. A string of that title removed elsewhere (a constant, a message) no longer lets a new test of that title pass as a case of the base.
- `tdd red` follows every dependency of a test file in turn: a fixture found by its name written with its folder (`fixtures/scan.ts`, a full path) brings the files it imports (`import type` included); a bare file name keeps the file a dependency without following it, and the text of a production module the test code imports directly (a constant naming a fixture) is searched for names too, one hop into production. A red run that records a case revised freezes the changed test code it depends on, as a red does: a fixture edited at review no longer leaves the gate failing with "test code changed outside tdd red".

- `--help` (or `-h`) after any command prints the help and runs nothing: `dialecte bench --help` no longer runs the bench and rewrites the baseline.
- A cli test no longer depends on an undeclared `jsdom`: the environment docblock it adds names `node`.
- The cli's test suite leaves no temporary folder behind: every test removes what it makes, also when it fails, and a vitest global setup (`test/suite-guard/`) gives the run one short temporary folder of its own (`dlt-<random>` under the system's, set as `TMPDIR` for the workers and the commands they spawn). At the end any entry left in it fails the run, named (ten, then `and <n> more`; Node's compile cache is not one), and the folder is removed whatever the outcome. One suite run left about a hundred `dialecte-hook-*`, `dialecte-skills-*` and `dialecte-facts-*` folders in `$TMPDIR` before.
- The cli's git reads (`git status`, `git diff`, ...) and the `gate` steps run with `GIT_OPTIONAL_LOCKS=0`: a read never refreshes the index, so a read made while a commit runs in the same repository never takes git's index lock behind it.
- Run inside a commit hook, nothing reaches the committed repository any more: git exports `GIT_DIR`, `GIT_INDEX_FILE` and the commit's identity to a hook, and the cli's tests spawn git in scratch repositories. A vitest setup file (`test/git-environment.setup.ts`) clears git's repository and config variables and the author and committer identity before any test. The cli clears at its start only the variables that point git at a repository, its index or its objects (`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`...), saying on stderr which ones it ignores when `GIT_DIR` or `GIT_WORK_TREE` named another repository than the folder's own (the `GIT_PREFIX`, `GIT_INDEX_FILE` and own `GIT_DIR` git exports to a hook or a `!` alias are dropped silently), so each git command it runs acts on the folder it names; git's config variables (`git -c` options, `GIT_CONFIG_COUNT`) still reach those commands.

### Changed

- `.dialecte/lot.json` takes a `mutation` key (`off`, `changed`, `audit`, `gate`), written by `dialecte lot mutation <mode>`: the lot's mutation switch. The lot file readers know the key, so a lot file holding it is no longer refused as an unknown key.
- `@babel/parser` and `@babel/traverse` (exact version 8.0.7, the ones StrykerJS 10 parses with) are devDependencies: the mutation runner's ignore rules and their tests read the syntax tree through them. The lockfile also moves the transitive `@jridgewell/sourcemap-codec` from 1.5.5 to 1.6.0.
- `dialecte worktree add` makes the links the new worktree's `file:` and `link:` dependencies need to reach sibling checkouts through `.worktrees/` (`.worktrees/core -> ../core` for `file:../core`), before copying `node_modules`: one outcome per dependency (`created`, `present`, `skipped: <target> missing`, `skipped: <folder> missing` for a path into a sibling not yet under `.worktrees/`, `skipped: outside .worktrees/`, `skipped: cannot make the link (<code>)`, `kept: points to <text>, not <target>`, `kept: a real folder`), never replacing what is there; a card row `links` and `siblingLinks` in the JSON. After the copy it reads `node_modules` against the worktree's `package-lock.json` (every package at its locked version, every link reaching what the lockfile resolves it to; bundled packages, and absent ones npm may leave out here - `optional`, an `os` / `cpu` list this machine does not match - not counted, a `devOptional` one checked; a lockfile that is not JSON or has no `packages` map is not checked): a card row `lockfile` (`✓ node_modules matches package-lock.json (<n> packages)`, or how many differ with the first five) and, when they differ, a `next` row with `cd '<worktree>' && npm ci`; `nodeModulesCheck` in the JSON; the exit code stays 0 whatever the links and the lockfile say. The `core` link a cli worktree needs is no longer made by hand.
- `dialecte worktree prune` never removes, nor offers to remove, a symbolic link or what a link reaches: a worktree path (a dangling one included: no `git worktree prune` for it), a hand-over folder or a rehearsal clone that is a link is kept as `a link: prune never removes a link nor what it points to`; a worktree, hand-over folder or rehearsal clone a link reaches (links looked for one level under the workspace, its `.worktrees/`, its `_commit-plan/` and the scratch folder) is kept as `the link <link> points to it`; a hand-over reached through a linked folder at any depth is kept as a link; while a registered worktree is a link, a worktree deleted from disk is kept naming it and no `git worktree prune` is offered (it would unregister the link's worktree too). `handover list` follows a link to a hand-over folder and lists a folder reached by its path and through a link once.
- `-h` and `--help` are read only before `--`: the words after it belong to the command (`dialecte coverage -- -h` hands `-h` to the command), for every command.
- `tdd red` flags `rollback` on every red of a run taken while production moved back: a production file moved back from the newest content the lot reached to its content at the base or at an earlier receipt, not only a production state the case's own receipts had left. The run prints one `rollback:` line naming the files before its summary. The ledger keeps, per base and per production state a receipt names, the content hash of each production file changed since that base (`production`, optional: a ledger without it detects nothing for the states it lacks; the same tree read at two bases keeps both). The receipts are walked in order: a green, or a receipt at a state moving nothing back, makes its state's contents the newest. A later red at code put back is flagged again, even after a run that only refused; a restore is not; a step a green proved (an experiment undone and kept) becomes the newest, so the next steps' reds are not flagged; a state put back adds no content (a file moved forward there is not back when it comes again); a green taken at code put back still becomes the newest and is flagged `rollback` with the same line only when a case it proves had no green receipt before (same file, name, project and test call; a refused run is no green, an earlier green counts whatever its flags): a refactor keeping proven cases green, dropping a file the lot added or putting a file back to its content at the base, is not flagged, and bringing back content it moved away flags the reds and first greens taken there; a state read at another base (a lot committed since, HEAD moved) is not compared.
- The cli no longer re-declares core's types: the definition, record and reader shapes are type-only imports from `@dialecte/core` (devDependency, erased from the build; the bin still loads the core of the user's project at run time).
- `@xmldom/xmldom` (exact version) is a devDependency: the `fixture` tests parse the documents they check in Node with it. The test workflow installs `xmllint` (`libxml2-utils`): the `fixture` tests judge every document of core's test dialecte against the XSD core ships.

- **Breaking:** needs Node 22.18 or later (`engines`): `dialecte run` loads `.ts` scripts through Node's built-in type stripping.
- `@dialecte/core` is a devDependency: the `schema`, `run` and `explain` tests drive its test dialecte (`DIALECTE_CORE_DIR` overrides it with a local build). For core's 0.8 train it is `file:../core`, held by the lockfile: the cli's checkout sits next to core's (`Dialecte/cli`, `Dialecte/core`), and a worktree under `Dialecte/.worktrees/` needs a `core` link beside it; the release pins a published core again.
- The cli follows `@dialecte/core` 0.8's test API: its tests call `assertValidXml({ xml, label, requireComplete })`, one object.
- `coverage` writes its temporary discovery file under `node_modules/.cache/dialecte/`, out of reach of formatters, linters and git.
- The hand-over card is made for the person who runs it. Title `hand-over: <repository folder> <branch>` (the repository and worktree paths and the run row left the box; the command stays under it). The verdict first: `READY` (no gate failed, none ran on another tree), `BLOCKED` (`<n> gates failed: <names>`, `gates ran on another tree: <names>`), `DONE` once a real run committed every lot - with the lots, files, `+<added> −<removed>` and `<n> declarations to read (below)`. Sections: `commit` (each lot's sha or `pending`, files, lines, subject; a merge lot's line, the lot sized from its recorded tree, else `size after rehearse`; `HEAD <sha>`, or `HEAD <base> → <tip> · nothing pushed` after a run), `gates` (one `✓` / `!` / `✗` line per step from the gate records, then `rules` from its record and `review` from the hand-over folder's findings ledger and round snapshots, `! review  <n> rounds · no findings recorded` while the ledger holds no row; `1 error`, `1 warning` in the singular; a record of another tree is marked `!` `(the tree changed since)` and blocks, a failed step stays `✗`; no record is `✗ gate  never run on this tree`), `tdd` (only the cases of the change, those the gate's tdd step listed on this tree: without a gate record of this tree that lists them, one line `counts from the last gate: run the gate on this tree` replaces the counts, groups, entries and flags; each case counted by the status the gate gave it: red then green as proven red → green (kept when its last receipt is a kept after a green), unchanged, accepted and revised in their own groups; `<n> accepted`, then one row per reason of the lot file (`<count>  <reason>`, the largest group first, a tie in the lot file's order, each reason wrapped under itself); `<n> revised · <m> gone · <k> unused  to read ↓` with one entry each; the earlier-lots line; flags counted per kind, with `helper code changed near unchanged cases (noise)` apart: a case whose only flag is `test code changed around it` and whose receipts are only unchanged or kept, so a rollback or a red after green never counts as noise), `notes` (the lots file's `gates` text, now free notes). Footer `dialecte handover --legend · details: dialecte tdd status` (too long for a narrow box: printed in it, above a plain closing rule). Its width is the terminal's columns, else `$COLUMNS`, else 80: the box is exactly that wide, every line wrapped with a hanging indent, never into fewer than 20 columns of text (a hang that would leave less is reduced; a commit line whose columns `<sha> <files> <+->` leave its subject less puts the subject, and a merge lot's merge line, on their own rows under it, 2 columns in; a line kept to one row with `…` is wrapped whole when its cut would keep less; a word wider than the room after the hang takes a row of its own, 2 columns in); colour only on a terminal, the `✓` `!` `✗` marks readable without it. `--json` changes shape: `gates` was the lots file's text and is now the array of gate lines (`name`, `status`, `detail`), that text moving to `notes`; `tdd` is the array of the tdd lines as the text a person reads (without the card's layout: a line's indent, a label's padding, a count's alignment, the `to read ↓` mark; the spaces inside titles, reasons and paths kept); it adds `verdict`, `failedGates`, `otherTreeGates`, `declarations` and each lot's `pending`. `commit.sh` says the lots file's text as `Notes:` in its header.
- The hook's output during `handover run` is read as steps from npm's script headers (a script running others with `npm run` or `run-p` is their parent; the lines of the scripts `run-p` runs stay the parent's). While the hook runs only the current step with its elapsed time and the warning and error lines (lint, format, type-check, build, failing tests) show: live under the spinner on a terminal, `│ ▶ <step>` and those lines off one; every byte goes to the full log. After a passing hook, one summary line (`check ✓ · test:run ✓ 1214 · build ✓ · 1 lint warning in lint:check`: the hook's own scripts, a nested one only with counts or when it failed), the warning lines and `full log: <path>`; after a failing hook, the summary with `✗`, the error lines not in the tail, the failing step's last 30 lines and the log's path. A hook printing nothing gets `hook ✓` (or `✗`) and the log's path; a repository with no commit hook stays silent (in husky's `.husky/_`, where every hook name has a wrapper, a hook counts only when its script exists in `.husky/`). Off a terminal the lot's `… lot n/N running <t>` line comes every 30 s in which no hook line was shown: lines the view filters out do not hold it off.
- Merge lots are trial-merged in sequence: each on the tree the lots before it leave (HEAD, each earlier plain lot's working-tree files, each earlier merge's trial tree with its resolutions), so a conflict that appears only on top of an earlier merge needs a resolution at the write instead of stopping the run. `merges.json` records that tree as `onTree`; the working-tree-change refusal leaves out the files earlier lots commit; the run refuses a merge lot before merging when HEAD's tree is not its `onTree` (an earlier lot committed other content: a hook staged files), naming both trees and the next step (see what the lots before it committed, then write the hand-over again from this HEAD for the lots left). A `merges.json` without `onTree` (written by an earlier cli) is refused at the read: write the hand-over again, then `--rehash` after a review. The state hash of the gate records builds a tree only, no commit object.

### Added

- A check's result belongs to the files it ran on. Every `gate` record and every commit hook record `handover run` makes holds its `key`: the git tree it ran on, what npm installed (`node_modules/.package-lock.json`, `none` without it), what ran (the gate's steps, with HEAD's commit when a step runs only the tests the change affects; or the hook files git runs) and the files the package's `file:` dependencies publish, read where `node_modules` links them (paths, sizes, modification times). A `files` exclusion is left out and a glob is walked from the folder before its wildcard (a superset of what npm packs). The key is taken before the steps and after them: a run whose state changed meanwhile is not stored, keeps the state hash of the tree its steps started on, and says so (`"stored": false` with `--json`). Records are also stored by tree in the repository's common git folder (`dialecte-checks/<tree>.json`), which every worktree of the repository reads.
- `dialecte gate` answers its steps from a green record of the same mode and key, made in any worktree of the repository: `reused: gate --<mode> green on this tree at <time> (HEAD <sha>)`, the record's step lines, `gate --<mode>: green (reused)` (`"reused": true` with `--json`), the worktree's record marked `reused` with the run it reuses. The hygiene and the `tdd` step still run every time (they are about the worktree, not the tree); a failed record, a record that ran no step, a record of the other mode and a record of an older cli are never reused; a stored entry of another shape is ignored. `--no-reuse` runs the steps whatever the store holds.
- `handover run --rehearse` rehearses only the lots that can find something new, and says why per lot (`lot <n>/<N>  reused  green gate --full on tree <tree>`, `lot <n>/<N>  rehearse  no green gate --full on tree <tree>`, `the lot changes package-lock.json`, `the hook stages files (git add)`, `main moved: the merge leaves tree <tree>, the tip holds <tree>`...). A plain lot is reused when a green `gate --full` of the tree its commit will hold matches what is installed now and its steps, the lot leaves `package-lock.json` alone and the hook stages no files of its own; a merge lot when the tree it leaves is its tip's and a green record of that tree (the branch commit's hook, or a `gate --full`) matches. When every lot is reused no clone is made (`rehearsal skipped: every lot's tree has a green record`, a reused merge's `tree <sha>` still printed); otherwise the reused lots are committed in the clone with `--no-verify`, the others with their hook, whose record goes to the repository's store marked as a rehearsal's. The decisions are written to `rehearsal.json` in the hand-over folder. `--rehearse --full` rehearses every lot. A real run runs every commit's hook, whatever the store holds.
- `dialecte skills generate` and `skills check` cover every function the package's entries export: each `package.json` `exports` subpath shipping a declaration file (`types`, or `types` nested one condition down such as `import.types`; `.d.ts`, `.d.mts` or `.d.cts`; a `*` pattern is skipped), read from its source under `src/` - the file, or the folder's `index`, with the declaration's extension, a `.d.mts` or `.d.cts` falling back to `.ts` - and a missing source stops the command, naming every path tried. The `api` block lists them after the method table, one section per entry in the `exports` order, headed by the entry (`@dialecte/core/sqlite`), with the columns Function, What it answers and Reach for it to. The `intents` block lists them by their route (`@dialecte/core/sqlite.connectHub`), and `skills check` requires the same JSDoc summary and `@intent` of them, naming the route. A function also bound on a root stays that root's row, its export route under `also`; one exported by two entries sits in the first entry's section. `@internal` functions and a dependency's re-exported ones are left out. `api.json` carries them with `root: 'export'` and `entry`, and `api find` scores their name without the entry. The check's summary line counts them apart: `<p> skill page(s), <m> method(s) and <e> export(s) checked`.
- `dialecte recap <hand-over folder>` prints a pull request's expandable part from the records only: the lots' commits, the test cases added (red then green, per test file), the gate and rules lines, the review rounds of the findings ledger (each finding with its id as written, every row of the file with the table's cell count, notes between rounds included, a row with no round refused; a hand-written state history read by its last transition, a state it cannot read refused), the decisions, the follow-ups, and the git user name of who posts it; a branch that does not hold the lots on top of the recorded base lists none as committed and says so. A `file:line` is printed relative to the repository, or to the workspace folder for a sibling repository, never absolute (an absolute path outside both, or one the rewrite does not reach, is refused); it writes nothing. `dialecte text check <file> [--kind pr|issue|comment|commit]` checks the human part of a GitHub text before it is posted: the fixed headings of a pull request or an issue (`What changes`, `Why`, `How to check it`, then `Watch out` when needed), no heading in a comment or a commit, a commit subject on line 1, not empty and of at most 72 characters, and a word cap (150, 200, 80, 100) that leaves out headings and code blocks. `dialecte record choice <folder> --by <who> <decision>` records a decision made outside the findings ledger in the hand-over folder's `decisions.md`, which `recap` prints.
- `dialecte gate` records its result in the worktree's git folder (`dialecte-gate-fast.json`, `dialecte-gate-full.json`): when it ran, HEAD, the state hash (of the tree the worktree would commit, `.dialecte/` left out: the same after the lots are committed) and each step's status, counts and note or reason, the tdd step with the cases of the change it judged (label and status); a run refused at the hygiene records nothing. `dialecte rules` without file arguments records `dialecte-rules.json` (when, HEAD, state hash, files, errors, warnings). The hand-over card reads its gate lines from these records.
- `dialecte handover --legend` prints every term of the hand-over card in two lines: what it means, and whether to look. `dialecte tdd status --legend` prints the tdd terms, shared with it, and works outside a package. `rollback` is a red, or a green run proving a case for the first time, taken while the lot moved production code back (a refactor green of cases already green is not flagged); `test code changed around it` is a case proven green whose test code (its own test file or a helper) changed around it after its green.
- A publish check: `prepublishOnly` runs `src/release-check.ts` before the build, which refuses a package.json naming a dependency by a local folder (`file:`, `link:`, `git+file:`, a bare `../x`, `./x`, `/x` or `~/x` path) in `dependencies`, `devDependencies`, `peerDependencies` or `optionalDependencies`, one line per dependency and how to pin it.

- No silent hang: every child that `dialecte gate` (its steps), `tdd` (its vitest runs) and `handover run` (each commit and its hooks, `--rehearse` too) start runs in a process group of its own, with its stdin closed, under a stall watchdog. Output (a part of a line included) or CPU time gained by its tree (descendants and process group, sampled with `ps` every 5 s, with a timeout) counts as activity; after 10 minutes with neither, the tree is printed (pid, state, CPU time, command), stopped (SIGTERM, SIGKILL after 2 s) and the run ends once its processes are gone, as `stalled`: the gate's step `stalled: no output, no CPU for 10 m 0 s` with the tree in its tail, `tdd`'s run with the tree, a hand-over lot not committed and unstaged (or, when a stopped git's `index.lock` stays, reported as still staged, naming the lock and saying to hand its path to the person who runs the repository). A `ps` failing for the whole 10 minutes is a stall too. Ctrl-C, SIGTERM and SIGHUP are passed on to every running child's group (a rehearsal stops the hook's group before it removes its clone). A child asking the terminal (a gpg or ssh prompt) is in a background group: it stops (state `T`) and is reported as stalled. The gate's steps and `tdd`'s vitest run are no longer synchronous spawns.
- `dialecte tdd red|green|status [<test file> | <test file>::<case name>]... [--json]`: a ledger in the worktree's git folder that makes the order of a lot's work visible. `red` runs every case of the changed test files with the package's own vitest (each project's run a case of its own; snapshots never written): a failure on an assertion, a snapshot mismatch, a stub's `not implemented` or a TypeError of existing code, inside an `expect(...)` a matcher completes, is a red; a passing new or changed case, a case whose test call changed since its receipt, a failure on a missing export, a type or syntax error, a timeout, a stub thrown at import or before the assertion, and a file holding `.only` / `only: true` are refused with their reason; a case the same as at the base is marked unchanged. One refusal records no red of its file; refusals are kept in the ledger. Reds record the hashes of the test file, of the case's own test call and of the production files, and are flagged `rollback` (a production state the case had left) or `red after green`. The run freezes the test files without a refusal and the changed helpers, fixtures and snapshots. `green` refuses test code changed since its freeze ("tests are frozen after red; go back to the test station"), a case without a red receipt, a green with nothing changed in production since its red, and a failure. `status` prints each case with its flags, the test code changed outside `tdd red`, and the cases the change deletes. A ledger that cannot be read is refused with its path.
- `dialecte gate --fast` and `--full` run a `tdd` step after the hygiene: every test-code file changed since the base as the red run that last froze it, every case of the change red then green (or unchanged); the flags and deleted cases printed under the step. A lot declared exempt in `.dialecte/lot.json` (`{ "tdd": "exempt: <reason>" }`, never committed: the hygiene and the hand-over leave the file out, wherever the package sits in its repository) passes with its reason and the count of production and test files the change touches; the hand-over card shows the same and the flags. A package that does not test with vitest skips the step.
- The tdd red run refuses a passing case still waiting for its green whose test file or imported test code changed since its red ("test code changed since its red and it passes"); a green case kept at such a run is recorded and flagged `test code changed around it`. A helper, fixture or snapshot is frozen only by a red of a file depending on it (relative imports followed through test code, a file named in its text, its snapshot). An error any existing code throws inside an asserting `expect` is a red, not only a TypeError. `red after green` flags only a case whose own last receipt is a green at the same production state. `.dialecte/lot.json` may accept cases without a red (`"accept": [{ "case", "reason" }]`), shown with their reason by the gate and the hand-over card. `dialecte new verb` writes its red case without `only`.
- `tdd` measures the lot from HEAD: on a branch holding earlier committed lots, only the uncommitted work is the change. `tdd ... --base <ref>` and `gate --base <ref>` give the whole-branch view (from where HEAD left the ref); `gate --full` measures from where the branch left its base branch (before a merge). Test code is compared by the leaves of the parser's syntax tree (each file parsed by its extension: a `.ts` file is no TSX): whitespace, comments (except `@vitest-environment`, `@jest-environment` and `@vite-ignore` ones), quote style, statement semicolons, trailing commas after an element and the order of import statements between side-effect imports are formatting, not an edit; template literals are compared by their raw text; any other change is. The ledger format is version 3: a version-2 ledger is refused with the advice to move it aside. A repository without a commit is refused in one line. A file with a refused case still records its other cases' receipts (it stays unfrozen); `green` takes a red recorded in a file never frozen as it saw the file. `"dialecte": { "tdd": { "production": ["src/test"] } }` declares folders whose files are production code (a package's test entry), except the test files, fixtures, snapshots and `*.script.ts` under them. `testCase.only ? it.only : it` (a runner picking per row) is no focus marker; a call through `.only` and `only: true` still are. `.dialecte/lot.json` may declare cases revised at review (`"revised": [{ "case", "reason" }]`; the case needs an earlier receipt, not necessarily a red): the next `tdd red` records a passing revised case as `revised` (a failing one is a red) and freezes the file again; status, the gate step and the hand-over card show them with their reason, and an entry no red run used as a note. `handover run --rehearse` removes the folders a deleted file leaves empty in the clone.

- `dialecte handover <lots.json>`: prepares the guarded commit-by-lots hand-over a human runs and holds the repository until every lot is committed (`gate` runs only under it; a hand-over of another folder is refused, naming the script holding the repository and its lock). It refuses (writing nothing) another branch or HEAD, a `core.hooksPath` naming a folder that does not exist (git would skip every hook: it says how to restore it), a staged file, a changed file in no lot or in two, plan tags and standard citations in files and messages. It writes the hand-over folder - the lots file, the snapshot (`files.txt`, `files.sha256`, `files.deleted`, and `lots.sha256`: an edit of `lots.json` after the review is refused) and a one-line `commit.sh` running `npx --no-install @dialecte/cli handover run <folder>` (bash re-exec; when the repository installs no cli that can run it, one line says so with the fix), nothing per lot - and prints the hand-over card and the command with its absolute `cd`; `--json` answers the same as data. `--rehash` after an edit.
- `dialecte skills check` refuses a method whose JSDoc summary or `@intent` still holds the `FILL:` placeholder `new verb` writes.
- `dialecte skills check`: fails when a skill cites an API, a path or an npm script that does not exist, links to a missing page, has invalid frontmatter or a stale generated block, or when a public method the package defines has no JSDoc summary or no `@intent` tag. It warns when a summary or an intent quotes a sentence, since the generated pages republish the JSDoc. `--workspace <folder>` also verifies pages that describe several repositories.
