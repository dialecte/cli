## [0.12.0] - 2026-11-23

### Added

- `dialecte lot approve` names the queue the host merges the change request through, as the host answers it for the change request's base: `queued (merge queue)` or `queued (auto-merge)`; nothing is added when the host offers neither or the read is refused, and a stacked lot's line names none. `dialecte doctor --host` probes this read.

### Changed

- **Breaking:** `dialecte lot approve` of a lot queued alone asks the host once which queue it offers the change request, before anything is recorded: a host that allows no auto-merge and has no queue on the base branch is refused (exit 1) naming what to turn on, with no approval recorded and no text sent. It used to record the approval and then fail at the host; running it again answered "already approved", and now refuses again until auto-merge or a queue is turned on. A read the host refuses refuses nothing: the queue goes ahead as before. A stacked lot reads no queue kind (it merges through the host's stack tool).
- **Breaking:** `dialecte worktree prune --yes` decides each rehearsal clone again right before its move, on the processes, links and lots read after the confirmation: a clone that is kept by then prints `✗ <clone> kept: <why>`, one gone since the plan prints `✗ <clone>: gone since the plan`, nothing is moved and the command exits 1, where it used to move the clone and exit 0.
- **Breaking:** a rehearsal clone whose marker pid runs again with another start time, and that no process works in, is now moved by `dialecte worktree prune`: the pid was reused, its rehearsal is over. It used to be kept for as long as that unrelated process lived.
- **Breaking:** `dialecte lot pr <id>` is now `dialecte lot describe <id>`, with the same `--print` and `--json`; `lot pr` is an unknown verb (exit 2, the lot usage). The pull request template's header comment names the new verb.
- **Breaking:** `dialecte lot review <id> --pull --round <n>` is now `dialecte lot review <id> --comments --round <n>`; `--pull` is an unknown flag (exit 2). The `pulled-comments.jsonl` record keeps its name, so comments already taken are not taken again.
- **Breaking:** `dialecte text check --kind pr` is now `--kind change-request`, still the default kind; `--kind pr` is refused with the usage naming the four kinds.
- **Breaking:** `dialecte worktree prune --yes` decides every item again after the confirmation - worktree, branch, committed hand-over folder, rehearsal clone, scratch and rehearsal hook folder, pool left-over - by the same rules as the plan, on a plan taken again right after the confirmation (the hand-overs found again, the processes, links, lots and markers read then, once, before the first move). An item goes only when that plan removes it with the same command; any other prints `✗ <name> kept: <why>`, `✗ <name>: gone since the plan`, `✗ <name> kept: not offered now`, `✗ <name> kept: removed another way now: <command>`, `✗ <branch> kept: its worktree stays`, `✗ <worktree> kept: git worktree prune would now also unregister <worktrees>` or `✗ <name>: not decided again: <reason>`, nothing is moved for it and the command exits 1, where it used to run the planned command and exit 0. An item only the second plan offers is never removed nor printed. A change made between two moves of one run is not seen; pool left-overs and rehearsal clones, read again right before their own move until now, are read at that one point.
- **Breaking:** a scratch folder, a rehearsal hook folder or a committed hand-over folder a process works in is now kept at the plan (`a process works in it: pid <pid>`), and kept with why when the processes cannot be listed; the processes are asked after every other rule.
- `dialecte lot review`'s approve line names the same refusal for a lot queued alone.
- The queued line of `lot approve` names the queue from that one read; the host is no longer asked again after the queue.
- Keep reasons changed: a worktree whose root `.dialecte/lot` link names a lot that is open, damaged or kept on purpose is now kept with that lot's reason (`lot <name> <state>`, its kept text) before any other rule, by `worktree prune`, `worktree prune --reclaim`, `lot close`, `lot close --feature` and `lot prune`; a store lot folder present but not read keeps it as `lot <name>: its records do not read`. A rehearsal clone whose marker cannot be parsed is kept with the marker reader's why.
- `dialecte worktree prune --json` gives a rehearsal clone item that goes its `owner`, the folder of the lot it belongs to.
- `lot describe`, `lot review` and `lot approve` name the change request in the host's own word: a repository whose origin is GitHub reads "pull request" as before; a repository no host serves (a local-path origin, no origin) reads "change request".
- The change-request template is the host's own: GitHub's `.github/pull_request_template.md`. A repository no host serves is read for the first host template its tree holds, and a refusal for a missing template names every path it looked for.
- Every printed line of `lot land`, `lot approve`, `lot stop`, `lot close`, `lot prune`, `lot status`, `lot describe` and the CI-first refusal of the hand-over verbs that names the change request uses the host's own word: a repository whose origin is GitHub reads "pull request" as before; a repository no host serves (a local-path origin, no origin) reads "change request". The rendered body's stale tests line says the same.
- Two lines read files only and so print "change request" on every repository, GitHub's included: the hand-over card's stack line, and `lot status`'s stack line when no landing is read.
- `lot stop` of a queued lot says its change request is "out of the queue", not "out of the merge queue".
- The help, the command reference pages, `README.md` and `AGENTS.md` say "change request" and "the queue", and quote no `gh` command; the CI pages name GitHub Actions' `pull_request` event by its name.
- A landed fact whose change request does not read is damaged with the reason "changeRequest is not a change request record".
- `dialecte worktree prune --json` gives every worktree item on a branch its `branch`, kept or not.
- The `worktree` page lists the exit codes of `worktree prune`.

### Fixed

- `dialecte worktree prune` no longer moves a rehearsal clone a process works in: a clone is decided by the same rules as in `dialecte lot close --feature`, so it stays while a process works in it, the processes cannot be listed (a lister that fails included), its lot is kept on purpose or damaged (a clone of a committed hand-over registered for exactly one lot's worktree and branch belongs to that lot; two such lots keep it, `owner not single: <lots>`), its run is alive, its marker cannot tell, a link reaches it, or the clone cannot be read; a plan never throws on an unreadable clone. A pid running again with another start time no longer keeps a clone nothing works in. `--yes` decides each clone again right before its move, on the processes, links and lots read after the confirmation: `✗ <clone> kept: <why>` or `✗ <clone>: gone since the plan`, nothing moved, exit 1.
- `dialecte lot close --feature` keeps the clones of a lot damaged by the time its clones are read at the plan, with the damaged text, instead of only at the move.
- A store lot whose `identity.json` does not read still holds what it held, found through the worktree's root `.dialecte/lot` link and through the registry entry naming its folder (`lot <name> damaged`): `dialecte worktree prune` keeps its worktree, its branch and its review throwaways; `worktree prune --reclaim`, `lot close` and `lot close --feature` keep its worktree; `lot prune` never takes its worktree for a hand-made throwaway and keeps its stack parent's branch, at the plan and again at the move. A worktree's root link names the lot that holds it for every remover: a lot it names that is open, damaged or kept on purpose keeps the worktree first, a lot folder present in the store but not read keeps it (`lot <name>: its records do not read`), and a lot folder gone or moved aside by `lot stop` holds nothing.
- A damaged lot kept on purpose now gives its kept text as its reason in `lot close` and `worktree prune --reclaim` too, as `worktree prune` did.
- Reading which host serves a repository spawns `ssh -G` once per ssh alias in a run, where every read spawned it again.
- `dialecte worktree prune --yes` no longer throws when the process lister throws after the confirmation: a pool left-over it would move is kept with `the processes are not known (<reason>)`, exit 1.
- `dialecte worktree prune --yes` no longer removes a worktree, deletes a branch or moves a folder kept since the plan: a worktree a process entered, changed or wrote an ignored file in, a branch a lot started on or a hand-over became pending on, a hand-over folder a process entered or a link reaches, a scratch or hook folder a process entered. It no longer deletes a branch whose worktree stayed, nor runs a `git worktree prune` that would unregister a worktree no confirmation covered, and the same branch name in two repositories is decided in each one.
- `tdd green` runs every case of the changed test files and of the test files moved with their bytes, and refuses
  every case that does not pass, whatever its proof: a red, an unchanged case, an accepted one, one revised by a
  case or file entry, or the base's case of a moved file. A case proven without a red records its proof again when
  its last run was at another production or at other bytes of its test file.
- The commit hook's tdd step refuses a commit holding a case of the lot that is not proven passing at the production
  committed, whatever its proof: `stale` (proven at another production) or `refused` (its last run refused it), both
  naming `dialecte tdd green`, or `unproven` (a case moved into a file a red ran before the move) naming
  `dialecte tdd red`. A case skipped as written is never listed.
- A test file git reports renamed is read at the base at its old path: its untouched cases stay `unchanged`, a
  `moved` entry may name that old path, a `gone` entry naming it is refused (a case removed in the rename is gone at
  the new path), and a file-level `moved` entry on a pair tdd matches itself is listed `not needed`, never `unused`.

A lot in flight that holds a test file moved with its bytes, a case proven without a red before a production change,
or such a case in a test file edited since its proof, needs one `dialecte tdd green` before its next commit. One
holding a case moved into a file a red ran before the move (the hook now lists it `unproven`) needs one
`dialecte tdd red`. A `gone` entry naming the old path of a git rename is now refused before any run: drop it with
`dialecte lot gone --remove <old path>` and declare a case removed in the rename as gone at the new path.

## [0.11.0] - 2026-11-22

### Changed

- **Breaking:** `gate --hook` holds every commit of a lot's branch to the lot's effective scope (its brief's scope with the `lot scope` changes) before any other step, the design step included. The lot's whole work up to the commit counts: everything since its lot base, a commit made earlier with the hook skipped included, both sides of a rename and every deletion. A path outside fails the commit, naming every such path and the `dialecte lot scope <lot> --add <path> --by lot-session --reason "<why>"` to run. Only the store's records in the `.dialecte/` folder of the repository root and of each package root (the folder of a tracked `package.json`) are left out; a `.dialecte/` folder anywhere else is held like any path. A review throwaway, a committed, canceled, failed or simulated lot, a first commit and a merge in progress skip the step; a damaged lot or a lot base that cannot be read fails it. A branch no lot names, the main checkout and a rehearsal's clone get no scope line.
- **Breaking:** `lot land` refuses a lot whose committed work leaves its scope (exit 1), naming the paths and the add, before any entry, rebase, push or pull request. A lot whose lot base reads as its own HEAD (no base branch found) is refused too: there is no base to check the scope against.
- **Breaking:** `handover run` of a store lot (and its `--rehearse`) refuses a lot whose committed work or pending files leave its scope, on a `scope` guard line, so a rehearsal sees what the commit hook would.
- **Breaking:** `--by orchestrator` is refused (exit 2, nothing run) for every verb that signs when it runs from a lot's own worktree or one of its `-round-<n>` or `-verify` throwaways, whichever `--by` of the line names it, in any casing and spacing. A lot signs `--by lot-session`; the orchestrator signs from the main checkout.
- **Breaking:** `lot scope --drop` refuses a drop that would uncover a file the lot committed since its lot base, not only one changed in its worktree, and refuses when the lot base cannot be read.
- **Breaking:** `dialecte changelog check` and `changelog release` refuse raw HTML in a fragment or the Unreleased part other than whole comments and bare tags with no attribute of `<b>`, `<i>`, `<u>`, `<s>`, `<em>`, `<strong>`, `<small>`, `<mark>`, `<del>`, `<ins>`, `<sub>`, `<sup>`, `<code>`, `<kbd>`, `<samp>`, `<var>`, `<details>`, `<summary>`, `<br>` and `<wbr>`, each closed inside the block or item a release moves (an item of a `- ` list, any other top-level block). An `<img src>`, an `<a href>`, a `<div>`, a `<script>` or a placeholder such as `<version>` written outside a code span is refused, the problem naming the piece and pointing to backticks; markdown links and images say the same.
- **Breaking:** `dialecte lot pr`, `lot land` and `lot approve` refuse a lot that changes package.json's version while its title does not name the new version, naming the `lot brief` command that corrects it; `lot land` pushes nothing and `lot approve` queues nothing. The version is read at the lot's own fork point, so a lot started on an open release lot sets none of its own. A base that cannot be read here (fetch it), a lot read against a base it shares no commit with, a damaged `stack.json` or a stack parent whose records do not read is now refused there too, never read as a lot not stacked; the tdd step of the gate refuses a damaged `stack.json` as `dialecte tdd` does.
- `lot verify`, `lot snapshot` and `lot delta` of a store lot read the lot's own worktree from anywhere, the main checkout included: the orchestrator verifies from there. A lot with no worktree (a simulated lot) is refused, naming it, nothing written.
- `lot approve` reads `--by orchestrator` in any casing and with spaces around it: refused on another package than the cli, recorded as `orchestrator` on the cli's own lots.
- `handover run --not-a-lot` and `lot brief` read their options like every other signing verb: the last value given wins, and `lot brief` takes no option after `--` (a `--by` there is a usage refusal, exit 2).
- `dialecte changelog release` puts each section's breaking items first: a `- ` bullet opening with a bold `**Breaking` (any case: `**Breaking:**`, `**Breaking (types):**`, `**Breaking** - ...`, `**BREAKING**:`) or the plain `Breaking:` / `Breaking (types):`, the Unreleased ones before the fragments', then every other block in the order written. Sections are read as CommonMark reads them (markdown-it 15.0.3, a new runtime dependency): each item of a `- ` list is a block, every other block (a list of another kind, a paragraph, a sub-heading, a fence, an HTML block or comment, a quote, a rule) is one block, never reordered, nothing inside a block is read as a heading or an item, and every line stays the author's own. A breaking item rises above a sub-heading or paragraph written before it. The section is written as oxfmt leaves it: a blank line after an item holding a second block and around any block that is no bullet item, one line feed between one-line items, so oxfmt no longer rewrites a released section. An Unreleased section written twice is merged with a blank line between its parts. A fragment or an Unreleased part holding an HTML comment, a code fence or an HTML block (`<pre>`, `<script>`, `<?`, `<!X`, `<![CDATA[`) that never closes is refused (`changelog check` and the release name it), never read as visible text. A version heading is a top-level `##` heading, as CommonMark reads it.
- `dialecte lot brief` changes a lot's commit message (`lots[<n>].message`), which titles its pull request; a lot's paths and the number of lots stay as started, refused naming `lots[<n>].paths` or `lots`.

### Fixed

- A cli older than the version a repository asks for runs no `dialecte lot` verb: it exits 2, naming the path it was started by and its real path, its version, the floor and where the floor came from (`--json`: `{ error, next: null }`), and writes nothing. The floor of a package is the cli repository's own version, else the lowest version its `@dialecte/cli` pin admits. A pin with no lower bound (`*`, `x`, an empty spec, `workspace:*`, `<2.0.0`, an `||` alternative without one) or no semver range (`file:`, `link:`, a path or url, `git+`, a dist-tag, `workspace:^` or `workspace:~` with no version after them) asks for the installed cli's version, and for no floor when none is installed. A package in a subfolder that does not ask for the cli takes the floor of the package above it, up to its repository's root. The repositories read are the current folder's package and those of each lot or brief the command line names; the highest floor decides. When the working tree's floor would refuse, the base branch's tip is read and the cli is refused only below both, so the main checkout's cli still lands a release or pin-bump lot. Equal or newer runs; help is never refused. The refusal hints the repository's own cli, `npm install` for a stale install, or `git -C <checkout> pull` for a cli checkout behind its release.
- The test suite no longer depends on a machine-global `@dialecte/cli`: npm's global prefix is an absent folder of the suite's own, so `npx --no-install` never finds a globally installed cli.
- `dialecte changelog release` no longer lifts a line hidden by raw HTML into view: an element opened in one item and closed in a later one counted as closed, and the breaking items moved first out of it. Every block or item now closes its own HTML.
- A tag inside an HTML comment is text: `<!-- <script> -->` between two items is no longer refused.
- The released-changelog rule (and `changelog check`) reads a run of blank and link reference definition lines that holds a definition as one blank line: a definition renders nothing, so adding a link line before text that follows the link block no longer reads as a change to the last released section, while a definition that splits a paragraph, ends an item or turns a line into indented code is still reported, at its own line.
- A fragment or Unreleased section keeps its first line's indentation: an indented-code `<!--`, `<script>` or `<title>` opening a section (or the Unreleased summary) was folded unindented, into raw HTML that hid what follows, older releases included. A section whose blocks, joined with the breaking items first, read otherwise (an indented block placed after an item joins it) is refused by `changelog check` and the release, naming the block, and at release the fragment it comes from and the one it joins.

## [0.10.0] - 2026-11-21

### Added

- `dialecte lot close --feature <name> [--json]` closes a feature at a pipeline's last step. It reads the feature's lots in every store of the list and refuses, exit 2, while one of them is neither committed nor canceled, listing each with its state. Otherwise it closes every lot worktree and recorded review throwaway of the feature on `lot prune`'s own proofs, leaves the branches to `lot prune` and does not list them, and moves the feature's dead rehearsal clones (their owner gone, or its pid reused) to their trash, each with `removing` and `removed` lines by `lot-close`. A clone that is alive, whose marker cannot tell, that a process works in, or that rehearses another hand-over (a pending one included) stays, named for `dialecte worktree prune`; one a link reaches stays, naming the link. A lot kept on purpose keeps every item, its clones included. Exit 0 when every item of the feature went, 1 when one stayed or the feature has no lot.
- A lot can be kept on purpose, so its worktree, review throwaways and branches stay after it is committed or canceled: `dialecte lot start <brief> --keep <why>` (or a `keep` field in the brief, never both) records the keep with the lot's first records, and `dialecte lot keep <id> --by <who> --reason <why>` and `dialecte lot unkeep <id> --by <who> --reason <why>` change it later, each a signed line of the lot folder's `keep.jsonl` and a `keep.changed` event. `lot unkeep` is refused from the lot's own worktree or one of its review throwaways. A keep never changes the lot's state, its scope's hold or any guard.
- `dialecte lot report --kept [--json]` lists every lot kept on purpose across the stores, real, simulated and damaged: since when, by whom and why, and whether its worktree and branch are still there.
- `lot report <id>` of a kept lot adds a `kept` line, and a committed or canceled kept lot whose worktree or branch is left names `dialecte lot unkeep` as next; `lot report --feature` marks a kept lot.
- The JSON of `lot status`, `lot answer`, `lot stop`, `lot wait` and `inbox` carries `kept`: `{ reason, by, at }`, the keep file that cannot be trusted, or `null`.
- The hand-over card has a `quality` row, read from the last `dialecte rules` record of the worktree: `! quality  2 duplicate reads · 3 shared exports changed (to read ↓)` with a `quality` section after `tdd` listing them (ten per kind, then `… <n> more (dialecte rules --base <short> --json)`), every one counted in the verdict's declarations to read. A public export left without docs and not opted out fails the row (`✗ quality  1 public export without docs: <route>`) and blocks the card; an opted-out finding is counted (`1 allowed`), never listed. A record of another tree, or whose base the lot no longer has, reads `! quality  record of another tree (dialecte rules)`: never stale, never blocking, nothing counted; no record reads `! quality  never run on this tree`. A `--base` record shows its lists `(since <short>, --base)` only when its base is the lot base or older, and never sets nor clears the docs row: that row stays the one of the last run without `--base` on the same tree (`docs: never run on this tree` without one, `docs: record of another tree` when its base moved). The card's `--json` holds `quality`. A public entry removed while a page still names it is a note of `rules`, never a docs finding: it neither fails nor counts. A record whose public API was unknown shows `docs: not judged (<why>)` and never passes. The row is left out only for a package with no `package.json`; with no record it reads `never run on this tree`, whether a base is found or not.
- The pull request body's risk part lists the base-aware findings under the risk line, judged on the committed head against the body's own base (uncommitted work ignored, no record read): `Quality: <counts> (since <short>)`, one line per finding not opted out as `dialecte rules` words it, ten per kind then `… <n> more (dialecte rules --base <short> --json)` (a public export without docs marked `✗`), then the notes `rules` prints: `public API: <route> removed: still named by <pages>` (once, never a `✗` line), `! public API unknown (<why>)`, `aliases changed: base edges read with the tree's`. The package.json, the public API index, the export sources and the doc pages are all read at the head. `Quality: not judged (<why>)` when the head holds no `package.json`, holds one that does not parse (`package.json does not parse`), or git cannot read the base, its diff from the base, its file list or a file it lists: a failed read is never taken as an empty change or text. The duplicate reads compare with the package's own api indexes the head holds, whatever its `exports` map, as `dialecte rules` does on the same tree. Its lines are checked as public text like every record text.

### Changed

- **Breaking:** `dialecte bench` measures the change against the base it goes onto, fresh, and writes no baseline any more: no `benchmarks/types/<version>/baseline.json` is read or written. The base is `--base <ref>` (its merge-base with HEAD), else the base handed in `DIALECTE_CHANGE_BASE`, else the order `dialecte rules` uses (the lot base of a store lot, the merge-base with the base branch, the last release tag). Both trees are measured with the head's compiler on one checker, one run per scenario; the base is exported into a scratch folder and removed after.
- **Breaking:** a scenario more than 5% over its base fails `dialecte bench --check` unless the change explains it: a line `- Type cost: <why>` it adds to its changelog fragment, or `Type cost: <why>` in its no-entry note. A line already at the base explains nothing.
- **Breaking:** `dialecte bench` exits 2 on every refusal (a base that cannot be read or is no commit, a lot with no base, no base with `CI` set under `--check`, a `node_modules` that does not install the lock, no version, a base tree that cannot be made or measured, method discovery failing at the head with `--check`); exit 3 is gone, and so is the `RUNS` variable.
- **Breaking:** `dialecte lot pr --json` names the change request `changeRequest`, not `pullRequest`: `{ title, body, changeRequest, head, sent }`.
- The CI template's type-perf job checks out the base the change goes onto and hands it to the bench in `DIALECTE_CHANGE_BASE` (the merge queue's base sha, else `HEAD^1`), skipped on a dispatch; `dialecte contrib` hands its type-bench step the base of the change, and a rehearsal with no base does not run that step.
- `landed.json` keeps the change request a lot landed through under `changeRequest`, not `pull`. A `landed.json` written before this keeps reading as landed: it names no change request, so its landed line says the pull request merged without a number.
- `worktree prune --yes` moves a dead rehearsal clone of the workspace's own `.worktrees/_scratch` into `.worktrees/_trash`, as it does a scratch folder there, instead of a `dialecte-trash` beside it.
- `lot close`, `lot prune` and `worktree prune` keep every item of a kept lot with `kept by decision: <why> (by <who>, <date>)`; `lot prune` reads the keep again at the move, so a keep written after its plan keeps the worktree, the throwaway and every branch. `worktree prune --reclaim` never touches a kept lot's own worktree, and health reports it as no idle worktree.
- A `keep.jsonl` that cannot be read, or holds a line that does not read, keeps the lot (never damaged); `lot keep` and `lot unkeep` refuse it, naming the file to repair.
- `lot stop` refuses to move a damaged kept lot aside; a kept lot stopped stays kept.
- No hint sends a kept lot to `lot close`: `lot status` and `lot wait` leave it out of `also`, `lot land` names the keep and `lot unkeep` instead, and `lot delta --worktree` says its throwaway stays with the lot in place of a removal command.
- `worktree prune` holds every damaged lot's worktree, review throwaways and branch, as `lot prune` and `lot close` already do.
- `lot design --approve` and `--waive` are refused from the lot's `-verify` worktree too, as from its own worktree and review throwaways.
- `dialecte-quality.json` is schema 2: every finding is kept with `allowed` (true when an opt-out silenced it); a schema 1 record reads as none. A `--base` run carries the docs findings of the last run without `--base` as `lotDocs`, with that run's tree and base.

### Fixed

- `lot close`, `lot prune` and `lot close --feature` keep every lot file of a landed or canceled lot's worktree, not only the root's: each package's `.dialecte/lot.json` (the folder of a `package.json` git tracks, or one the lot deleted) is archived in the lot's folder as `lots/<package path>/lot.json`, or `lot.landed.json` beside one holding other bytes, before the worktree goes. Before, a non-empty package lot file kept the worktree for good.
- A lot file counts as archived only against an archive of its own package path; before, any archive of the worktree's hand-overs matched any lot file.
- `lot close` reads every lot file it counted again right before the move: one rewritten since the close decided keeps the worktree, naming it, with nothing archived; an archive is never written over one and is read back, and a write that fails keeps the worktree with its error.
- `worktree prune` (and every removal outside `lot close`) no longer counts a landed lot's live lot files as archived: only `lot close` archives a lot's own lot files, so a worktree whose lot file nothing archived is kept.
- The health `worktrees` rule compares a lot's worktree by its real path, as git registers it: a worktree its lot names through a linked folder is no longer reported idle.

## [0.9.0] - 2026-11-20

### Added

- `dialecte doctor --host [--vendor <name>]` runs every read the lot verbs make of the repository's host once, for real, through the same code: the newest merged pull request (read by number, a branch with none, its checks, its queued state), a reference pull request's line comments, and the stack extension; then the host tool's versions against the recorded ones and git against its floor. It prints only those lines. It exits 1 on an error (a read refused, an answer whose shape changed, git below 2.38, no host vendor for the origin); a warning (nothing to probe, the stack extension absent, a tool older than recorded) never fails. `--vendor` names the vendor to probe whatever the origin says.
- `dialecte lot prune [<id>...] [--feature <name>] [--all] [--yes] [--json]` removes what a committed or canceled lot leaves behind: its worktree, its review throwaways (recorded by a step, or cut by hand at a commit of the lot) and its branches, each item on its own proof. Without `--yes` it prints the plan; `--yes` acts, each proof read again at the move, a branch deleted only at the tip proved. A lot's work is its worktree's HEAD plus its uncommitted work, taken as one snapshot commit on a copy of the worktree's index (`add -A`, `write-tree`, `commit-tree` with a fixed identity and date, so the same work gives the same sha); the worktree's index, refs and files are never written, and ignored files stay out. A person fact by `<who>`, `unchecked: true` when the ask read no documents or went `--person-only`; `answer.json` in the ask folder (`schema: 1`). On an ask the outside readers answered, the person confirms it: a person fact supersedes the outside fact (it stays `unchecked: true` while the ask read no documents, so it is asked again once documents exist) and `<ask>/confirm.json` (`schema: 1`, `{ ask, fact, by, at }`) marks the ask confirmed; a second confirmation is refused (exit 2, naming it confirmed); every other answered ask stays refused. `--verdict` keeps that verdict on the person fact (`value`: the answer as its value), so a later re-ask whose readers agree with it supersedes it; without it the fact says `person` and a re-ask's readers are shown to the person; another word is refused (exit 2, naming it and the four). `--cite` (with `--quote`) is checked as a reader cite against the whole documents and recorded as a reader miss (given or not to a reader, and the first round) or `citeRefused` (a cite into a file changed since the ask: `file-changed`), the answer recorded all the same. `--json` (`schema: 1`): `ask`, `fact`, `miss`, `citeRefused`. Exit 0 recorded, 2 usage or a refusal (an unknown or answered ask, one made before the readers, another run holding the ask). Events `ask.answer` (`{ rung: 6, miss, citeRefused }`) and `ask.state`. `lot answer` on the question an ask raised records the same person fact through a registered `onAnswered` hook (synchronous, the lot note written before it returns).

A claim file holds its holder's pid and start time; a pid running under another start time (`ps` run in the C locale) is a pid reused, a claim of a gone process is taken over once older than its stale limit, under an exclusive `<claim>.takeover` file, and any claim held more than 10 minutes is taken over.

The squash commit takes this title and body, so they hold the lot's final state, never its commit bodies. The title is the brief's first commit message; the body holds the brief's `summary` and its other commit messages, each step's title and behaviours, the changelog fragments the lot adds (or its no-entry note's reason), `tests.json` (a part taken on another tree than the committed head reads `stale`, never its counts), `review.jsonl` (each finding's id, round, severity, file and how it closed, then each verdict by its reviewer's kind - a review station, verify, orchestrator or person - never a name; a row holding a value its writer never writes is refused, naming its record), the risk class and effort, the overlaps the lot accepted (the other lot by its index only, and why, never the met paths or who accepted them; `none` without one), and `Closes #<issue>`. The tests box ticks only with a gate record of the tree without a failure, else it says `gate: not recorded, CI is the proof`. A damaged lot is refused. The open pull request is edited only when its title or body reads otherwise (`pull request #<n> updated from the lot records`); `--print` sends nothing; without a pull request the text is printed and `lot land <id> --draft` named; a merged or closed one is refused.
- The body's free text (messages, summary, step titles, behaviours, changelog lines) is checked before anything is sent: a reference of the lists (ticket, citation, declared pattern, consumer name, forbidden word), an entry id of the plans that hold the lot, a link, or a path git does not list in the lot's tree or at its base is refused (a changelog line is committed text, public already: a path relative to the tree passes there, a link or an absolute, home or parent path does not), naming the label, the word and the record to rewrite (`lot pr: the pull request text holds a <label> \`<word>\` in <record>: rewrite that record, nothing sent`).

The new brief passes the start's field and public-text checks; it replaces the stored brief, and a `brief` transition records the sha256 of the brief it replaced and of the new one (`brief: { from, to }`), who and why, the lot's state and position kept.

- `dialecte rules` has a `class` rule (error): Dialecte code is functional first, so a class passes only when a package entry exports it (a typed public facade: the `exports` map of `package.json`, followed through `export *`, `export * as`, `export { a as b } from`, an imported name exported again, `export default`, and a const or a type alias naming the class, type-only exports included; `export *` never carries a default), when it `implements` an interface (a store), or when it is a data-only error. An entry's names admit only the module-level class they name, never a local class of the same name. A data-only error extends `Error`, a base named `*Error` or such an error of the same file, and holds only fields, index signatures and a constructor made of `super(…)`, `Object.setPrototypeOf(this, …)`, locals and `this.<field> = …`, each value data: no function, method, getter, class expression, call (`.bind(…)` included) or `new` in it, and no name the file shows holding a function (a parameter declared with a function type or default, a local or module const holding one, a module function or class); any other name read, an import, a global or `new.target.name`, is data. All of it is inferred from the code, no config. Any other class is an error naming the class and the ways to pass; it is kept only with `// dialecte-allow class: <why>`, on the line before the class or in the comments right before it, its doc comment included. Like the other quality rules, in a run with a gate base an error on a line the change does not add is a warning.

### Changed

- Every record key reads its lock from the tree it checks, never from `node_modules`: `lockHash` is the sha256 of the `packages` of that tree's `package-lock.json` (keys sorted, the package's own `""` entry left out; `none` when the tree holds none). The gate and contrib read the worktree's state tree, the commit hook the index it commits, the hand-over card its checked tree, the rehearsal plan each lot's tree. A card, a rehearsal or a landing on another worktree, a pooled or a copied `node_modules` no longer reads "gates ran on another tree" for a tree whose records are green. Records written before run once more (their key held the installed lock).
- `gate` (every mode), `gate --hook` and `contrib` refuse, exit 1, no step run and nothing recorded, when `node_modules` does not install the lock being checked: `node_modules does not install the package-lock.json being checked: <package>: <what differs> (and <n> more); run cd <package> && npm ci`; when the checked lock is a staged one that differs from the file on disk, the line says to put that lock on disk (or stage the one on disk) first; a checked lock that cannot be read package by package refuses too. A hook given another repository's index checks nothing.
- `gate --fast`, `--full`, `--release` and `contrib` honour `DIALECTE_CHECK_STORE` as `gate --hook` does: they read and write that store, their records marked `origin: rehearsal`; a value that is no absolute folder is ignored with `gate --<mode>: DIALECTE_CHECK_STORE ignored: <why>` (`contrib: ...`) as the first line.
- `dialecte gate --hook` runs the full gate's steps itself, but the scoped ones that count no tests (for a package with the default list: check, skills, build, tests; a scoped `rules` step stays the gate's and contrib's). Each step is answered by any green record of the committed tree and install that ran it as it is now - a `gate --fast`, `--full`, `--release` or an earlier hook's - with one line `gate --hook: reused <step> from <mode> <at> (HEAD <short>)` naming the run that really ran it; the steps no record answers run in one go. A scoped step is answered by a record of the same base, or by one that checked everything (a `--release` run, recorded at the empty tree). Every hook run with a HEAD writes a `hook-gate` record of the index tree (`dialecte-gate-hook-gate.json` and the repository's store). A record written by an older cli (no step hashes) answers the test steps only while its whole key still matches (it keyed the install on the lock's bytes: in practice only with no installed lock); elsewhere the steps run once more. What to change: make the package's `.husky/pre-commit` the single line `npm run test:hook` (`"test:hook": "dialecte gate --hook"`): `check` and `build` lines before or after it now run a second time.
- `DIALECTE_CHECK_STORE` is honoured only when it names a git common dir (an existing folder holding a `HEAD` file and an `objects` folder); any other value (relative, missing, empty, a partial folder) is ignored with one line `... ### Changed

- Breaking: a lot's effort now follows its risk class. Each lot or hand-over folder keeps a `risk.jsonl`: `effort` lines a person records and `derived` lines the cli appends (`{ kind: "derived", class, reasons, from }`, the last line winning). The class is derived from the lot's changes: `high` for a changed file in the package's `dialecte.risk.high` list (the base's and the worktree's together, so a change that drops a glob still counts it), an added destructive call or git argument in a source file (a comment-only line is not read), or a runtime package (one with an `exports` map) whose API index or, without an index change, export source changed; `light` for docs, a version bump, the lockfile, or at most 40 changed lines in at most 3 files; `medium` otherwise. The cap of review rounds is the rounds of the higher of the effort's class and the derived class (low or light 1, medium 2, high 3), and the effort is the last `effort` line, else the lot's own. The cap no longer reads the folder's `brief.json` `effort`: a folder with no effort recorded refuses a round past the first, exit 2, naming `dialecte lot risk <folder> --effort low|medium|high --by <who>`. What to change: record the effort of such a folder with `lot risk --effort` before its second round, and give `lot start` an effort below its scope's risk class only with `--by <who> --reason <text>`. New `dialecte lot risk <id|folder> [--json]` prints the class derived now with its reasons (a declared one as `<file>: declared [<glob>]`), the effort, the cap, and `! effort <e> below risk class <c> (by <who>: <reason>)` when it is below (`(no go-ahead recorded)` when no reason is recorded), writing nothing; when the class cannot be derived (no commit yet) it falls back to the last derived line, else `unknown`, and ends with `! risk class not derived: <reason>`, exit 0; `--json` follows the versioned schema `src/commands/lot-risk.schema.json`; a damaged store lot is refused, exit 2; `lot risk <id|folder> --effort low|medium|high [--class high|medium|light] --by <who> [--reason <text>]` appends an effort line (the same effort, class and reason again: `already`, nothing written), an effort below the class needing `--reason` (exit 2 otherwise, also for no `--by`, a forbidden word or a committed, canceled or failed lot). `lot start` takes its default effort from the class of the brief's scope, asks for the effort on a terminal (without `--json` or `--dry-run`) with that default, and refuses an effort below the class (exit 2, nothing written, a dry run too) unless `--by <who> --reason <text>` give the go-ahead, recorded on an effort line. `lot snapshot` derives the class again before the cap check, appends it only when the snapshot goes ahead (a refused snapshot writes nothing), names what set the cap in its refusal (`(effort medium)`, or `(effort medium, risk class high)` when a class raised it) and prints `! risk class now <class> (<reason>): cap <cap>` when it is above the effort; `handover write` appends a derived line too, so a finished card never derives again; a derivation that cannot run prints `! risk class not derived: <reason>` and appends nothing. `lot status --json`'s `effort` gains `riskClass` and `below` (`source` `risk-line` for an effort recorded by `lot risk`, `riskClass` the last derived line or `null`), and the text form adds the below line. A file of a staged lock change git cannot read is refused by the lock sync (`<file> in the index could not be read: <reason>`, exit 2), never installed as absent. ### Added

- `dialecte ask "<question>" [--about [<Parent>/]<Tag>[@<attr>] | --code <code> | --method <path>] [--kind <kind>] [--decision] [--package <name>] [--effort low|medium|high] [--lot <id|folder>] [--limit <n>] [--no-facts] [--no-standard] [--person-only] [--json]` (Discover): answers a question about the installed dialecte from the cheapest source that holds the answer, and hands the question on (to readers of the documents, or a person) instead of guessing past the dialecte's own files. The subject is read from the names of the installed dialectes the question holds (exact names, case kept; a name that is also an ordinary word counts only as `@name`, `name=` or through `--about`); `--about`, `--code` and `--method` name it instead and `--kind` forces the kind. A tag of several installed dialectes needs `--package` unless the folder is one of them.
- The ask's answer ladder, the first rung that answers ends the ask: rung 0, the current fact of the same question in the facts ledger, reused when it is valid at the asked effort or above (a person's fact at any effort; any other fact is listed as a candidate, never the answer; `--no-facts` reads and records none); rung 1, the definition, for a structural question whose element resolves to one declaration (`--about <Parent>/<Tag>` for a tag declared several ways); rung 2, the Dialecte catalogue (`explain`) for a code and the api index (`api find`) for a method (the entry whose intents hold every content word of the need, else the closest five); rung 3, the standard's slices: `find`'s own list for the whole question first, then up to 3 slices of angles taken from clauses that list did not cover, then the linked slices, handed to readers. A rung 1 or 2 answer is recorded as a fact at the ask's effort, and checked again when the definition changes (the same answer keeps it with the new hash, else it is stale and a new fact replaces it).
- The outside route: the documents are the `DIALECTE_STANDARD` folder whose id has the key of the dialecte's declared standard name (every folder when it declares none). With no documents the ask skips rung 3 and goes to outside readers; `--no-standard` is refused while documents are readable for the dialecte and is the outside route without them; `--person-only` sends the ask to a person after rung 2. Once documents exist, each `unchecked` fact of the dialecte's standard is asked again, once: a new ask holding its question and `reask: <fact id>` (never its answer), and a `rechecked` line on the fact.
- `dialecte ask --decision`: the definition is the boundary of what is valid, never the answer. It is read live (`boundary` in `--json`) when the question is structural and resolves to one declaration; the answer comes from the prose inside it (a standard or person fact, or the readers), and prose naming what the definition rejects is answered within the boundary. A standard-versus-XSD conflict is flagged (`conflict: { kind: 'standard-vs-xsd', fact, outside }` in `--json`, `! conflict: ... the XSD wins - fix the XSD and ask again` in the text) and the ask still exits 0: the XSD wins. Without `--decision`, `boundary` and `conflict` are null.
- `dialecte ask` states and exit codes: `answered` exit 0; `needs-person` exit 1 (next: `dialecte ask answer <id> ...`); exit 2 for usage and refusals with nothing written (an unknown `--about` tag or attribute, an attribute the element lacks, several dialectes without `--package`, two standard folders of one key, `--no-standard` with documents, an `--effort` other than the lot's, a `--lot` folder inside a repository); `needs-readers` exit 3 (next: `dialecte ask pack <id>`, with `--outside` without documents). `ask pack` and `ask answer` are refused as not built yet.
- The ask folder `A-<n>` holds `ask.json`, the `--json` object (`schema: 1`: the subject, kind, rung, state, answer, fact, source, boundary, conflict, candidates, methods, angles, slices, effort, next and what was read of the documents). It is kept in `<lot folder>/asks/` with `--lot <id|folder>` (a store lot by index, name or folder, or a hand-over folder outside every repository) or when run in a lot's worktree, else in `$XDG_STATE_HOME/dialecte/asks/`. An ask of a lot that reaches the documents or the outside route rewrites the lot's `standard.json` `consulted` note (every ask of the lot and its state). A lot's ask takes the lot's effort; elsewhere `--effort`, else `medium`.
- The `ask.parsed`, `ask.rung` (one per rung run, with its time), `ask.fact` and `ask.state` events go to the lot's `events.jsonl`, else `$XDG_STATE_HOME/dialecte/asks/events.jsonl`. They hold the question's length and key hash, never its text, a quote or a slice's text; `ask.state` says `conflict: true|false`, never what conflicts. An event that cannot be written prints one line on stderr and never changes the exit code.
- `dialecte standard eval <gold.jsonl> --angles`: the gold run through the ask ladder instead of `find` alone (kind `semantic`, no fact read or written, no ask kept, no event), `find`'s own list first and untouched, then at most 3 slices of angles from clauses it did not cover, then the linked slices. A question the ladder refuses scores `find`'s own list. The answer adds `added +<n>` (`added` in `--json`): the items whose quote only the added slices hold.
- `@dialecte/cli/lookups` exports `findInStandard` and `loadStandardIndexes` with their types (`FindInStandardParams`, `StandardSearchIndex`, `StandardSlice`, `LoadStandardIndexesParams`, `LoadedStandardIndexes`, `LoadedStandards`, `AskStandard`, `StandardReadyIndex`, `StandardInstalledVocabulary`, `StandardFolder`, `StepProgress`). `findInStandard` is pure; `loadStandardIndexes` builds a missing or outdated index and writes it to the index cache.
- `dialecte rules` checks quality rules. On implementation files: `argument-mutation` (error: a function changes what a parameter refers to; return the new value instead), `query-in-loop` (error: a query read on a query binding inside a loop or loop callback; read them in one query before the loop; not run without an API index), `long-function` (warning: over 60 lines of code; split it). On test-shaped files (test files, `-fixtures.ts`, `.test-fixtures.ts`, `-cases.ts`, files under the package's top-level `test/` folder): `table-branch` (error: an act branches on a case field), `without-export-xml` (error: a `.withoutExport(` act reads exported XML), `export-without-queries` (error: a `.withExport(` case without queries), `fixture-builder` (warning: a function builds fixture XML), `plan-tag` (error: a title, table key or file name carries a plan or round tag). A finding of these rules can be opted out with `// dialecte-allow <rule>[, <rule>]: <reason>` (a reason of 15 characters at least) on its line or the line before (for `argument-mutation` and `long-function`, also in the comments before the function, its doc comment included); a malformed opt-out is an `invalid-allow` error, one that covers nothing an `unused-allow` warning; `--json` and the rules record count the findings silenced per rule in `allowed`. An API index that cannot be read fails nothing: `query-in-loop` does not run and one line names the file.
- `handover run`'s install guard, real run and rehearsal: before each lot's commit (its files staged, after the existing lock sync, which brings `node_modules` to a staged lock change), `node_modules` are read against the lock the commit holds, the index's `package-lock.json`, for every lot. A package installed at another version than it, missing or a link elsewhere refuses the lot, exit 2 (a failed commit stays 1), nothing committed for it or the next, its files unstaged again (a merge lot's merge aborted): `✗ lot <n> not committed: node_modules do not match package-lock.json: run npm ci in <worktree>` (the repository's worktree, shell-quoted, never a rehearsal clone), or, when the working copy holds another lock than the index for git (`git diff --quiet`, line endings applied: a later lot's), `✗ lot <n> not committed: node_modules do not match the package-lock.json lot <n> commits (a later lot changes it): run npm ci with that lock, or commit the lock change first`; then `    <package>: <problem>` for the first 5 packages and `    and <k> more`. It fails closed, exit 2 and the lot undone in each case: an index lock that the guard cannot read as a lock refuses the lot (`package-lock.json <unreadable|has no packages map>: run npm ci in <worktree>`), one git cannot read too, an unmerged one included (`package-lock.json in the index could not be read: <reason>`), a lot staging a lock that does not parse is refused by the lock sync before any install (`package-lock.json in the index does not parse: <reason>`), and a check that throws refuses with its reason. Each check writes the hand-over folder's `install.json`, replaced whole: `{ "at": <ISO time>, "lock": <sha256 of the index lock>, "working": <sha256 of the repository worktree's lock, left out without one>, "ok", "mismatched": <n> }`, plus `"laterLock": true` when the lot was refused with the later-lot text (git's view; absent on every other record); a record that cannot be written prints `! install.json not written: <reason>` and the lot goes on. Every hand-over card (still to run or DONE) shows it as its `install` gate line, read from that record only (never from the packages on disk): `✓ install  node_modules match package-lock.json (<first 12 of the index lock hash>)`, `✗ install  node_modules do not match package-lock.json (<n> package(s)): run npm ci in <worktree>`, `✗ install  node_modules do not match the package-lock.json the next lot commits (<n> package(s)): a later lot changes it: run npm ci with that lock, or commit the lock change first` for a `laterLock` record, or `✗ install  package-lock.json could not be read: handover run refuses until it reads`; a failed line turns a card still to run BLOCKED, never a DONE one. The line shows while the worktree's lock hashes to the record's `working`; no record, one that cannot be read or has a field missing or of another type (a `laterLock` that is not a boolean included), or a worktree lock that moved since (or none now): no line. No lock in the index: nothing checked, nothing written, so across lots an earlier lot's record stays when a later lot deletes the lock. When the guard finds the index lock unreadable it removes `install.json`, so the card shows no stale pass for that lock (a refusal of the lock sync leaves an earlier lot's record as it is).
- `dialecte gate` in a repository without package.json reads a root `dialecte.json` (`{ "schema": 1, "gate": { "fast": [...], "full": [...], "release": [...] } }`, `schema` optional), which overrides the inferred steps list by list: a list it lacks is inferred, and with nothing to infer it must declare both `fast` and `full`. Any other key, and a `gate.skip` (there is no default npm step to opt out of), is refused: `gate: dialecte.json: <problem>`. A repository with a package.json is unchanged and never reads `dialecte.json`.

A pending hand-over is abandoned first (the logic of `handover abandon`, now one library function both run); a run in progress or a hand-over committed meanwhile refuses the stop (exit 2, nothing published). Then a `canceled` transition with the reason and who stopped it (`caller` by default), and the registry read once more so a hand-over registered meanwhile is abandoned at once. A lot already canceled exits 0 writing nothing; one left with a `pending` entry is repaired. `committed` exits 2. It moves no worktree and deletes nothing. The `next` of a failed lot (`dialecte lot stop <full name> --reason <text>`) and of a ready lot without a hand-over (`dialecte lot result <full name>`) now run.
- `dialecte inbox [--repository <name>] [--simulated] [--json]`, in the Grow family: what waits on someone across every store of the store list and the store of the current folder, one line per open question (person, then caller), then the ready and the failed lots, by index within a group, each with its exact next command; then `working <n> · simulated <m> (listed with --simulated)`. `--repository` keeps one repository folder by name; `--simulated` lists the simulated lots that wait; a lot folder whose identity does not read, or whose records do not hold, is a `damaged <folder>: <reason>` line. A lot's records are checked once, on read (a question id `q<k>` with k 1 or more, an audience `caller` or `person`, a position's step, of and round non-negative integers, a transition's `at` a time, an answer file's question its file's `q<k>`): a lot that fails reads damaged, every lot verb refuses it (exit 2), and no forged field reaches a line or a `next`. Reads files only, each registry once per store, runs no process. `--json`: `{ waiting, working, simulated, damaged }`, `waiting` the status of each waiting lot. Exit 0 when something waits or is damaged, else 1; 2 for a usage error.
- Agent text the lot verbs print in their text form (`status`, `wait`, `answer`, `result`, `stop`, `inbox`: question texts, stations, options, recorded answers, who answered, reasons, notes) shows control characters, bidi overrides and isolates, bidi marks and line separators as `\u{<hex>}`; each field is escaped whole before it joins a line, so a line feed in it prints as `\u{a}` and never adds a line of its own; `--json` carries the text as stored. A question raised with a station or an option holding a line break (LF, CRLF, lone CR) is refused, as a multi-line question text already was, nothing published.
- Every answer of `lot status`, `wait`, `answer`, `result` and `stop` prints on standard output whatever its exit code (0, 1, 3, 4, 5); only a usage error or a refusal (exit 2), and an answer hook that threw (exit 1 of `answer`), print on standard error; `inbox` follows the same rule. `lot start` stays outside it: a refused start (exit 2) or a failed one (exit 1, the lot `failed`) is an error on standard error, naming the lot and its next command. The answer line a `next` names for a caller's question carries no `--by` (it defaults to `caller`); a person's keeps `--by <who>`. A simulated lot's `lot status` carries its start's findings in `checks.wouldRefuse`.

Exit 2 for an unknown or ambiguous id (`{ error, next: null }` with `--json`) or a usage error (`{ error, usage, next: null }`).
- The lot store, `<git common folder>/dialecte-lots/`: one folder per lot (`brief.json`, `plan.md`, `identity.json`, `transitions/`, `answers/`), each record published whole and once, read-only; a lot folder is built aside and renamed into place, and the leftovers of a writer that died are removed by the next one.

- `dialecte standard index | find | show | eval`, in the Discover family: the index of the standards kept on the machine, outside every repository. `DIALECTE_STANDARD` names a root folder holding one folder per standard (its lowercased name is the standard's id; its top-level `.md` files are the standard, a file's id `<standard id>/<name>`). The index of each standard lives in the cache only, `$XDG_CACHE_HOME/dialecte/standard/<id>/<manifest hash>/` (else `~/.cache/dialecte/`; the manifest hash holds the index format, 2, so a folder of an earlier format is never reused), built into a temporary folder and renamed into place, reused while the files are unchanged (`--rebuild` forces a build), aborted when a file changes during the build; the links to the vocabulary are a file of their own, named by the selected dialectes' `name@version` list and added when it changes. The vocabulary is the tags, attributes and enumeration values of the dialectes installed where the command runs, or of the one `--package <name>` names on `index`, `find` and `eval` (not installed: exit 2 naming the installed ones): exact names, case kept, never stemmed, scored like a word (no link strength, weighted by the lines naming it); a name in lowercase letters only, from three characters, is searched as a word. Those three verbs print `vocabulary <name@version>[, ...]` (or `vocabulary none (no dialecte installed)`) first, and `vocabulary: { packages }` in `--json`. Other words are searched by their stem (plural, `-ied`, `-ying`, `-ing`, `-ed` and a final `e` removed), common, modal and question words left out; an acronym (capitals and digits, two capitals or more) is kept from two characters, never split nor stemmed, its plural with one lowercase `s` searched as the acronym. A slice starts at the first hit of its unit's densest window (at most 60 lines holding the largest weight of distinct terms; a table at its caption when that window ends within 60 lines of it) and runs to the unit's last hit, capped at 60 lines; the unit's score is unchanged. `index` prints each file's quality (verdict, noise, headings, tables, definitions, repeated lines); `find "<terms>" [--about <Tag>] [--limit <n>]` the ranked slices of whole lines with their original line numbers, then the clauses they refer to `[linked]`; `show <file id>:<from>-<to>` the normalised text of a range; `eval <gold.jsonl>` the recall at 5 and 10 of `find` over a local gold file (an item's expected quotes are alternatives, matched in plain words without their markdown markup), with the reason of each miss. `--standard <id>` picks one standard. Refused with exit 2: no root configured, a root that is a file, holds `.md` files directly or holds no standard folder, colliding ids, an unknown standard or file, a root, standard folder or cache inside a git work tree. A `--rebuild` puts the new folder in place before the old one is removed, so a reader never sees a half-removed index.
- `dialecte skills check` verifies every cli invocation a skill page cites in code (inline code and fenced blocks of any language, generated blocks left out) against the command map of the cli the package uses: the cli's own map in the cli itself, else the installed `@dialecte/cli`'s `dialecte --help --json`. An unknown command, verb or flag, or an old renamed form (`dialecte record review`, `dialecte review delta`, `dialecte recap`), is an error printed as `page:line`, naming the closest valid form (`dialecte lot finding`) or, with none close, the valid verbs or flags. `<!-- dialecte-skills ignore: ... -->` skips the finding whose word it names. With no installed cli, or one before the map, the invocations are not checked and one warning says why; the exit code does not change for it.

- The `node_modules` pool: `.worktrees/_pool-<repository>-<n>/node_modules` with a `pool.json` (`{ repository, lockHash, parkedAt }`, `lockHash` the sha256 of `package-lock.json`), at most two entries per repository. A park takes only a `node_modules` that matches its `package-lock.json`, rewrites absolute in place the links leaving it by a relative path, renames the folder in, sends `.vite` and `.cache` to the trash, then writes `pool.json`; a take renames the newest matching entry out. Used only where the repository's parent holds `.worktrees/`.

- `dialecte lot close <hand-over name|index>... [--json]`: for each committed or abandoned hand-over of the registry named, its worktree (the path the registry entry holds) sent to the trash, then its `node_modules` parked in the pool from there; the branch never touched. Kept with why, nothing done: a pending hand-over, the main checkout, no registered worktree at that path (or one in the trash or the pool), a worktree on another branch than the hand-over's (both named), a locked worktree, a mutation run from it, a process working in it, the processes not known (`lsof` failed or timed out), a dirty worktree. Each line names the folder it moved and where `node_modules` went (`pooled in <entry>` or `trashed: <why>`). Exit 0 all closed, 1 one kept, 2 a name or index the registry does not hold.
- Scoped gate steps and `dialecte gate --release`. A gate step may say `"scoped": true`: it gets `DIALECTE_GATE_BASE` and `DIALECTE_GATE_TREE` (the base and tree the gate resolved once), `DIALECTE_GATE_CHANGED` (the changed paths, NUL-separated) and `DIALECTE_GATE_SELECTION` (where it writes its selection JSON `{ schema: 1, base, tree, changed, selected: [{ id, reasons }], skipped: [{ id, reason }] }`), and is judged on that selection; the base is `--base <ref>`, else the merge-base with `dialecte.baseBranch` (default `main`), else the empty tree, and enters the record's key. `"heavy": true` marks a heavy suite (outside the command hash). `dialecte gate --release` (alone) runs `dialecte.gate.release` (default: the `--full` steps) with every scoped step against the empty tree and records `dialecte-gate-release.json`; a green release record of a list that covers full answers a commit hook, a rehearsal's lots, contrib's steps and the card. `gate --hook` on a scoped package prints `gate --hook: base <sha> (<source>), selected <ids>|nothing selected|reused`, and `handover run` hands its hooks the hand-over base (`DIALECTE_HANDOVER_BASE`, `DIALECTE_HANDOVER_FOLDER`); hook records are keyed with the base the hook printed. The card says what a scoped step selected since its base, reads a record of an older base as current (`(older base)`) and one whose base moved as stale, and prints `✗ gate  invalid gate config: <message>`; `handover write --release` marks a release hand-over (`"release": true`), whose card requires a `gate release` row. An invalid gate config exits 2 (`gate`, `contrib`, `handover run`, nothing staged) or 1 (`gate --hook`). A package without a scoped step keeps its command and hook hashes; every failed or flaky step now records its failing files and the card's row of a failed step shows them; the hook's running line now says `no green gate --full or --release`.
- A failed gate step records the files its whole output names as failing, with those a scoped step's selection declares (`"failing": [...]`, paths relative to the package root), sorted and unique: `failing` on the record's step and in `gate --json`, and the card's row of a failed step ends `· failing <n>: <first 3>[, +<k> more]`. A scoped step counting tests whose command (or the npm script it runs) names no vitest is rerun serially like a vitest step, whatever runs it, when it exits non-zero on a test failure - a failed test counted, a `FAIL` line, or vitest's error markers (`Unhandled Errors`, `Errors  <n> error`) - and never when its selection was invalid; a plain script error fails as itself. The rerun gets its failing files after one `--` only through `npm run` (a direct command gets them as plain arguments), then `--no-file-parallelism`.

### Fixed

- `dialecte tdd` resolved no import that carries a Vite query or fragment (`./x.worker?worker&url`, `?raw`, `?url`, `?inline`, `#part`): such a test file was refused, `cannot resolve the import`, and got no receipt. The query and the fragment are left out of the file the specifier names, for relative, tsconfig `paths` and vite alias specifiers alike; a specifier starting with `#` (a subpath import) is read as before, and one whose file does not exist is still unresolved, named as written.
- `dialecte tdd` froze no fixture an `import.meta.glob` reads unless the test's text named the file: each pattern of a glob call (relative to the file, `/` for the package root, or a vite alias) now makes the changed files it matches dependencies of the test; a negated pattern (`!./fixtures/skip.xml`) leaves its files out, and names none.
- `dialecte handover run` of a hand-over whose lots are all committed, the working tree edited since (a later merge, a later edit), was refused at `head` ("other content than the reviewed files"). Committed lots are now compared with the reviewed snapshot (`files.sha256`), not the working tree; when every lot is committed the `head` line says `the hand-over is already committed`, the guards that read the working tree are not run, and the run exits 0. A lot committed by hand with other bytes than reviewed is refused at `head`.
- `dialecte worktree add <path>` whose path is no folder (the repository named from inside itself) threw `Cannot read properties of undefined`; it and a folder in no git repository now answer one line, exit 2.
- `dialecte worktree add` and the `node_modules` pool made a link from `node_modules` into its own checkout (an npm workspace package, `node_modules/@s/pkg -> ../../packages/pkg`) absolute, so the copy or the pooled `node_modules` reached the old checkout's package. Such a link now stays relative; a link leaving the checkout (a sibling repository) is still made absolute.
- A merge hand-over whose commit hook ran on the merged tree (`handover run --rehearse`, or the real commit) still read `BLOCKED ... gates ran on another tree: tdd, skills, tests`: the worktree's `gate --full` record, of its tree before the merge, stayed on the card beside the hook's lines. A hook record of the tree the hand-over commits, not dropped by a newer gate record of that tree, now replaces the lines it answers of every gate record of another tree (a gate run on the worktree's own tree after the rehearsal included), as a newer gate record already replaces a hook record's: the card reads `check`, `build` and `test:hook` from the hook (`· commit hook · rehearsal`) and no `tests` line (the hook counted tests); a step the hook did not run reads `! skills  not run on the merged tree`, a warning that does not block, and a failed one stays `✗ ... (the tree changed since)`; and the `tdd` line is the worktree's, stale only when the worktree changed since its gate run. Once a merge hand-over is committed, its card keeps `! tdd ... (the tree changed since)` and `gates ran on another tree: tdd`: the worktree took the merge after its tdd verdict.
- `dialecte worktree prune` read every hand-over's repository twice per repository of the workspace and its state up to three times: on a workspace of 8 repositories and 173 hand-overs it spawned 7259 git processes and took two minutes. Each hand-over's repository is now read once, and its state once.
- `dialecte tdd` let an acceptance override a proof: a case proven red then green, still named by an `accept` entry, was recorded `accepted` at the next `tdd red`, and once the entry was removed no command could bring back its red → green (a `revised` entry on it was ignored, `kept  proven before (accepted)`). Now an acceptance never overrides a proof, and a receipt counts only while the lot file declares it; nothing in the ledger is rewritten:
  - `tdd red` on a passing case proven red then green, an `accept` entry naming it: no `accepted` receipt; the case goes the normal path (`kept`, flagged `test code changed around it` when the test code moved) and the line adds `acceptance not needed (proven red → green): it can be removed from the lot file`. An acceptance on a case without that proof is recorded as before.
  - `tdd red` on a proven case nothing changed since its proof, a `revised` entry covering it: `kept  <case>  proven before (<kind>)  revision not needed (nothing changed since its proof): <reason>`, no receipt; the gate still lists the entry as unused.
  - An `accepted` receipt whose `accept` entry the lot file no longer holds, or that a red then a green of the same case precede, and a `revised` receipt whose `revised` entry (exact, file or glob) is gone, are skipped: `tdd red`, `tdd green`, `tdd status`, the gate and the hand-over card read the case from its earlier proof. A case whose file was frozen again after its green then owes a fresh `tdd green`, which it can now get with no test edit.
  - `tdd status` and the gate's `tdd` details print one line per case with skipped receipts: `skipped  <case>  1 accepted receipt (no longer declared)` (or `(proven red → green before it)`). The hand-over card names each such case of the change among its entries to read (`skipped <file> › <case>: <receipts>`, counted in the head line and in the declarations to read), and `earlier lots:` counts only cases outside the change.
- `dialecte tdd` asked a new red for every case of a test file split into several (or cut out into another file), although the cases were the base's own. A case of a new or changed test file is now **moved**, and reads like a case of the base, when its test call (by the tokens its case hash reads) under the same describe path was in the base text of a test file the change deletes, or of a changed one that no longer holds it there; nothing to declare:

  - `tdd status` and the gate's details print one line per source file, `moved  <n> case(s)  <old file> → <k> file(s)`, ending with ` · test code changed around them` when a target's code outside its test calls (imports, hooks, helpers) differs from the source's; the hand-over card's tdd section shows the same line. A deleted file cases moved out of is reported by that line, not as `the test file of the base is deleted`.

  - Cases a helper registers (the call at their location is no test call: `checkRow(row)`, `defineLeg(...)`) are **moved by name** when a test file the change deletes, or that registers fewer cases now, registered at the base one case of the same name and project through a runner too: `moved by name  <n> case(s)  <old file> → <k> file(s) · runner changed: <base call> → <new call>`. The base names come from one collect-only run of those base files (no test executes), only when a split is detected without running anything (a test file deleted, or a changed one whose base ran a registering statement, such as `for (const row of ROWS) checkRow(row)`, it no longer runs; a row added to a table is no split), in a scratch copy of the base tree outside the worktree that is removed after; `tdd status` prints its duration (`base collect  1 file(s)  0.8 s`), and it is stopped past 5 minutes.

Its second line is now `if [ -z "${BASH_VERSION:-}" ] || shopt -oq posix 2>/dev/null; then exec env -u POSIXLY_CORRECT bash "$0" "$@"; fi`, before the header comments, on a fresh write and after `--rehash`; `POSIXLY_CORRECT` is unset for the new bash, which it would put back in posix mode.

Naming any other label (a citation of a standard) fails both commands with the list of allowable ones.

## [0.2.1] - 2026-11-03

### Added

- `dialecte gate --hook [--no-reuse]`: the test steps of the package's `gate --full`, for a commit hook. A green `gate --full` record of what is committed answers them instead of running them: same key as the gate's store (the tree, what npm installed, the `file:` dependencies, the full gate's command hash), the tree taken from the index git hands the hook (`GIT_INDEX_FILE`, else the worktree's index), never from the working files, so a merge commit's hook and a partial commit check what they record. One line says which: `gate --hook: tests reused from gate --full green on tree <tree> at <time> (HEAD <sha>)`, or `gate --hook: no green gate --full of tree <tree> with this install: running the tests` before the test steps (rerun serially on a failure, one vitest summary line of their summed counts after them). No hygiene, no tdd step, no hand-over hold, no record; `--no-reuse` runs the tests whatever the store holds.

### Changed

- The cli's own `check` script no longer runs the suite (type-check, lint, format); its pre-commit hook runs `check`, then the suite through `npm run test:hook` (`gate --hook`), then `build`. A lot whose tree passed `gate --full` commits and merges without running the suite again: a one-commit lot and its merge (onto a main that did not move) run the suite once instead of five times (fast gate 1, full gate 2, commit hook 1, merge commit hook 1). The hook still runs it for a tree no green `gate --full` checked: the earlier commits of a multi-commit hand-over, a merge onto a main that moved, any commit when a full step runs only the changed tests (its command hash holds HEAD).

### Fixed

- `handover run` keys a commit hook's record by the tree the commit records (the index just before `git commit`), not by the working files: a lot committed while a later lot's file is already edited, or a merge lot before such a lot, has its hook record under its own commit's tree. A hook's test step that `gate --hook` answered from a `gate --full` record is recorded with a note naming that run (`reused gate --full of <time> (HEAD <sha>)`), and its card line reads `reused by the hook`.

## [0.2.0] - 2026-11-03

### Added

- `dialecte mutants run | status | schedule | abandon | migrate`: mutation testing of the scope a package declares in `package.json` (`"dialecte": { "mutation" }`). `run` mutates the scope lines changed since the merge base with the base branch (else the remote's default branch, else it refuses with exit 2; `--base <ref>` for another one), or the whole scope with `--mode audit`; without `--mode` it follows the lot's switch. The run is written `running` (process id, worktree, branch, lot, tree, mode, base) to `<git-common-dir>/dialecte-mutation/runs/` before Stryker starts and replaced `reported` with its counts and survivors when it ends, so a run killed mid-way reads `died` from any worktree of the repository. Tiers in order: fast, the timed-out mutants alone, the declared full tier on the survivors no committed record lists. Survivors no record lists enter the ledger `<git-common-dir>/dialecte-mutation/ledger.json` as `new` and stay there until a later run detects that exact mutant (`killed`; never a run that started before the last run reporting it), a record explains them (`recorded`), or `schedule <follow-up>` moves them to `scheduled`; a survivor whose line changed or went away stays pending. The last lines name the package, lot, tree, mode, counts, each new survivor and each ledger item the run moved to `killed` or `recorded`; survivors never fail the command, a failing Stryker exits 1. `status [--json]` lists running runs with their age, died runs, new survivors by lot and scheduled ones by follow-up; `abandon <run id>` marks a died run abandoned and keeps it; `migrate` turns `scripts/mutants/equivalent-mutants.json` into `.dialecte/mutation-records.json`. A run records its owner process's start time too (a pid now held by a process that started at another time reads `died`), names an empty Stryker config file so a package's own `stryker.config.json` is never merged in, refuses a detached HEAD, and removes its work folder (`.tmp/mutants/<run id>/`) once reported. The ledger's readers and writers hold a lock file (a lock whose owner process is gone, or that names no owner and is a few seconds old, is taken over) and first take in, in the order they started, any reported run whose ledger update was missed; a scheduled survivor follows the same rules and keeps its follow-up. Stryker's incremental file is kept per package and key in `<git-common-dir>/dialecte-mutation/incremental/` (seeded into the run's work folder, written back after a reported fast tier; the key holds the whole tree, the lock, the linked dependencies, the fast options, the cli version and the ignorer's bytes), so it is reused on an identical tree only and never across edits; the newest 4 files of a package are kept, and a failed write-back only prints a warning. The build ships the ignore rules Stryker loads as `dist/ignorers.js`.
- `dialecte mutants judge | record | drop`, and `--json` on every `mutants` verb but `run`. `judge [--file <file>]` prints the package's new survivors as capped per-file packets (10 survivors, 12000 bytes of JSON and of text each): per survivor a family guess with its reason, the covering tests the last run named (a run entry's survivors now carry the first five covering test names, sorted, and how many more), the code around it as it is now with the mutated lines marked and a flag when its line changed since the run, and the `record` / `schedule` commands. `record (--key <key>... | --file <file>) --family <family> --reason <text> [--removable]` writes the records to `.dialecte/mutation-records.json`, then moves the new or scheduled survivors to `recorded`, under the ledger lock and records first (`unclassified`, an unknown family or key, an empty or over-200-character reason refuse the call and write nothing). `drop <run id>` removes an abandoned run, or a reported run, from the store; it refuses a running or died run and the latest reported run of its branch (it is that branch's evidence: drop it once a newer run of the branch reported). With `--json` a verb prints exactly one JSON object on stdout, `{ "verb", "ok", ... }` or `{ "verb", "ok": false, "reason" }`, whatever its exit code.
- Pending mutation work now blocks the hand-over. The `dialecte handover` card gets a `mutation` line (after `rules`, for a package that declares a mutation scope): `✗` and BLOCKED on `new` survivors or died runs of the package (`2 new survivors · 1 died run: dialecte mutants status`), on a run still running that a merge hand-over or a `gate` lot waits for, and on a `gate` lot with no run of its branch reported on the tree it commits (`gate lot: run dialecte mutants run on this tree first`); `!` for a run of the branch still running on a plain hand-over (`its survivors are not in yet`); else `✓ nothing pending`. `handover run` checks the same thing again as its last guard, `mutation`, when it runs: a survivor reported or a run that died after the card was written refuses the run (exit 1, nothing committed), each survivor and died run listed with what to do (a test that kills it, `dialecte mutants record --key <key> --family <family> --reason <why>`, `dialecte mutants schedule`, or rerun / `dialecte mutants abandon`). `dialecte recap` gets a `Mutation` section: the runs of the lot's branches with their counts, the survivors they killed or recorded, the lot's scheduled survivors. `dialecte worktree prune` keeps a worktree a mutation run was started from while the run runs or after it died unreported.

A hook printing nothing gets `hook ✓` (or `✗`) and the log's path; a repository with no commit hook stays silent (in husky's `.husky/_`, where every hook name has a wrapper, a hook counts only when its script exists in `.husky/`). Off a terminal the lot's `… lot n/N running <t>` line comes every 30 s in which no hook line was shown: lines the view filters out do not hold it off.
- Merge lots are trial-merged in sequence: each on the tree the lots before it leave (HEAD, each earlier plain lot's working-tree files, each earlier merge's trial tree with its resolutions), so a conflict that appears only on top of an earlier merge needs a resolution at the write instead of stopping the run. `merges.json` records that tree as `onTree`; the working-tree-change refusal leaves out the files earlier lots commit; the run refuses a merge lot before merging when HEAD's tree is not its `onTree` (an earlier lot committed other content: a hook staged files), naming both trees and the next step (see what the lots before it committed, then write the hand-over again from this HEAD for the lots left). A `merges.json` without `onTree` (written by an earlier cli) is refused at the read: write the hand-over again, then `--rehash` after a review. The state hash of the gate records builds a tree only, no commit object.

- A check's result belongs to the files it ran on. Every `gate` record and every commit hook record `handover run` makes holds its `key`: the git tree it ran on, what npm installed (`node_modules/.package-lock.json`, `none` without it), what ran (the gate's steps, with HEAD's commit when a step runs only the tests the change affects; or the hook files git runs) and the files the package's `file:` dependencies publish, read where `node_modules` links them (paths, sizes, modification times). The check's summary line counts them apart: `<p> skill page(s), <m> method(s) and <e> export(s) checked`.

A new case still needs a red; a case whose title is computed is refused ("not provably a case of the base: accept it or prove it red"). The card lists only the accepted and revised receipts the current lot file names, the others folded into `earlier lots: <n> accepted, <m> revised (not in the lot file)`, and the `gone` entries.

- A merge as a hand-over lot: `{ "kind": "merge", "branch", "tip", "resolved": { "<path>": "<file>" }, "message", "tree"? }` in `lots.json`. The write checks the tip (gone or moved: refused), the conflicts of a trial merge against the resolutions, and the resolutions (missing, conflict markers: refused), and records the conflicts and their hashes; `--rehearse` prints the merge's tree, which a real run requires. The run merges the recorded tip, checks conflicts, resolutions, conflict markers and the tree before the commit (aborting the merge on a refusal) and the tree again after it; a done merge is recognised by subject, second parent and tree; a merge in progress of something else is refused and left. A hook's output is never buffered: its full log is written as it runs. - No silent hang: every child that `dialecte gate` (its steps), `tdd` (its vitest runs) and `handover run` (each commit and its hooks, `--rehearse` too) start runs in a process group of its own, with its stdin closed, under a stall watchdog. Output (a part of a line included) or CPU time gained by its tree (descendants and process group, sampled with `ps` every 5 s, with a timeout) counts as activity; after 10 minutes with neither, the tree is printed (pid, state, CPU time, command), stopped (SIGTERM, SIGKILL after 2 s) and the run ends once its processes are gone, as `stalled`: the gate's step `stalled: no output, no CPU for 10 m 0 s` with the tree in its tail, `tdd`'s run with the tree, a hand-over lot not committed and unstaged (or, when a stopped git's `index.lock` stays, reported as still staged, naming the lock and saying to hand its path to the person who runs the repository). A `ps` failing for the whole 10 minutes is a stall too. Ctrl-C, SIGTERM and SIGHUP are passed on to every running child's group (a rehearsal stops the hook's group before it removes its clone). A child asking the terminal (a gpg or ssh prompt) is in a background group: it stops (state `T`) and is reported as stalled. The gate's steps and `tdd`'s vitest run are no longer synchronous spawns.
- `dialecte tdd red|green|status [<test file> | <test file>::<case name>]... [--json]`: a ledger in the worktree's git folder that makes the order of a lot's work visible. `red` runs every case of the changed test files with the package's own vitest (each project's run a case of its own; snapshots never written): a failure on an assertion, a snapshot mismatch, a stub's `not implemented` or a TypeError of existing code, inside an `expect(...)` a matcher completes, is a red; a passing new or changed case, a case whose test call changed since its receipt, a failure on a missing export, a type or syntax error, a timeout, a stub thrown at import or before the assertion, and a file holding `.only` / `only: true` are refused with their reason; a case the same as at the base is marked unchanged. One refusal records no red of its file; refusals are kept in the ledger. Reds record the hashes of the test file, of the case's own test call and of the production files, and are flagged `rollback` (a production state the case had left) or `red after green`. The run freezes the test files without a refusal and the changed helpers, fixtures and snapshots. `green` refuses test code changed since its freeze ("tests are frozen after red; go back to the test station"), a case without a red receipt, a green with nothing changed in production since its red, and a failure. `status` prints each case with its flags, the test code changed outside `tdd red`, and the cases the change deletes. A ledger that cannot be read is refused with its path.
- `dialecte gate --fast` and `--full` run a `tdd` step after the hygiene: every test-code file changed since the base as the red run that last froze it, every case of the change red then green (or unchanged); the flags and deleted cases printed under the step. A lot declared exempt in `.dialecte/lot.json` (`{ "tdd": "exempt: <reason>" }`, never committed: the hygiene and the hand-over leave the file out, wherever the package sits in its repository) passes with its reason and the count of production and test files the change touches; the hand-over card shows the same and the flags. A package that does not test with vitest skips the step.
- The tdd red run refuses a passing case still waiting for its green whose test file or imported test code changed since its red ("test code changed since its red and it passes"); a green case kept at such a run is recorded and flagged `test code changed around it`. A helper, fixture or snapshot is frozen only by a red of a file depending on it (relative imports followed through test code, a file named in its text, its snapshot). An error any existing code throws inside an asserting `expect` is a red, not only a TypeError. `red after green` flags only a case whose own last receipt is a green at the same production state. `.dialecte/lot.json` may accept cases without a red (`"accept": [{ "case", "reason" }]`), shown with their reason by the gate and the hand-over card. `dialecte new verb` writes its red case without `only`.
- `tdd` measures the lot from HEAD: on a branch holding earlier committed lots, only the uncommitted work is the change. `tdd ... --base <ref>` and `gate --base <ref>` give the whole-branch view (from where HEAD left the ref); `gate --full` measures from where the branch left its base branch (before a merge). Test code is compared by the leaves of the parser's syntax tree (each file parsed by its extension: a `.ts` file is no TSX): whitespace, comments (except `@vitest-environment`, `@jest-environment` and `@vite-ignore` ones), quote style, statement semicolons, trailing commas after an element and the order of import statements between side-effect imports are formatting, not an edit; template literals are compared by their raw text; any other change is. - `dialecte skills sync`: installs the agent skills your dependencies ship in `skills/<name>/` into `.claude/skills` and `.agents/skills` (`--agent claude,copilot,agents`, `--copy` instead of links, `--from <folder>` to take them from local checkouts). Only what it installed is ever replaced or removed. Its manifest records the package and version each skill came from.
- `dialecte run <script.ts>`: runs a module script (its default export gets `{ project, doc, documentId, dialecte, helpers, utils }`) against an in-memory project of the installed dialecte and answers one outcome - the thrown error as code, key, detail, `meta` and the element's path, the input's import diagnostics, the operations per tag, what the script returned. `--in` imports a file first, `--out` writes the result, `--prepare` stages the first transaction and commits nothing (its operations and its callback's report), `--expect <file>` checks a JSON array of `{ tag, where?, under?, count? }` and names each one not met with the count found. Ids are seeded (`--seed`), `--now` freezes the clock: the same script, input and seed give the same outcome. `--json`, `--package`, `--timeout`. Exit 1 when the run failed or an expectation is not met. Records are counted as each commit merges them. Under `--prepare` every other write is refused and fails the run, even caught (a second transaction, a prepared commit, another document's transaction, the project's writes and raw database); in every mode a callback may not call `tx.commit`, `tx.finishStaging` or `tx.clearStagedOperations`. Needs `@dialecte/core` 0.8.0.
- `dialecte fixture <Tag> [--under A/B] [--package <name>] [--out <file>] [--json]`: the smallest XML document holding an element that is valid against the dialecte's full schema - structure, values, identity and references - built by the installed dialecte's engine with its hooks: the chain of parents from the root (the shortest, or the `--under` path), every child required on the way and the first branch of every required choice, the first variant of an element of an abstract type, a value for every required attribute and for text an empty value does not satisfy (fixed, default, else the first value the type takes, every facet checked: enumeration, pattern, length, range), each sampled value new in the document so unique and key fields never repeat, and for every reference a keyref checks the element it points at - one already planned when the values can meet, else one planted along the key's selector. The document is the plain export, without record-id marks. Ids are seeded and the clock frozen: the same command gives the same bytes. Exit 1 with the reason when there is none: an unknown tag (the closest named), a `--under` step its parent does not hold, a value it cannot make (the attribute named), a reference it cannot plant (the constraint named), a write the engine refuses. Needs `@dialecte/core` 0.8.0 (`requiredChoices`).
- `dialecte explain <code | key>`: what an error or diagnostic code means, when it is raised, the usual fix and the docs page, from the catalogues of the installed core and dialecte. `--json`; exit 1 for a code no catalogue knows.
- `dialecte skills generate`: rewrites the generated blocks of your skills from the source: verb map of your extensions, core method index, hook files, and the API index (`api`: every method with its JSDoc summary and `@intent` tags; `intents`: "when you need to... → use").
- `dialecte api find "<need>"` and `dialecte api show <path>`: find a method by what you need and read its contract (signature, summary, intents, routes, where it is declared, a call a caller can copy) from the `api.json` the installed packages ship, without the repositories. Methods rank by the words of the need their intents hold, then their summary, then their name.
- `dialecte members <expression>`: what `doc.query`, `doc.query.reference` or `tx.lifecycle.extract` hold, from the live types of your package, one line per member.
- `dialecte schema <Tag>`: parents, children with how often each may appear, attributes with their rules, text and xsi:type variants of an element of an installed dialecte, read through the core that dialecte resolves; an unknown tag answers the closest tag names.
- `dialecte doctor`: installed `@dialecte/*` versions, the core API generation of each dialecte (a warning when one runs on another core than your app), synced skills against node_modules (missing skills, copies of another version), local checkouts; each warning with the command that fixes it.
- `dialecte skills generate` writes `api.json` next to the page holding the API index, with each method's declared signature and one call: its JSDoc `@example` when short and calling the method, else a test call without test scaffolding in its arguments; `skills check` fails when it is missing or stale.
- `dialecte rules`: the code-rules self-check on the syntax tree of the changed files (or the files given): types outside `*.types.ts`, module constants outside `*.constants.ts`, functions declared as `const`, an `await` inside an argument, plan tags and standard citations are errors; positional parameters and abbreviated names are warnings. `--json` for a program.
- `dialecte rules` reports a test that takes the system's temporary folder itself as its root - `tmpdir()` handed to a call that lists or scans a folder, or given as a root option (`root`, `cwd`, `scratchRoot`...) - as an error: other tests and processes share that folder; a folder of the test's own (`mkdtempSync(join(tmpdir(), '<prefix>-'))`) fixes it.
- `dialecte gate [--fast | --full]`: runs the package's Definition of Done step by step, unfiltered, and judges each step on its exit code and the counts it printed (a test step that counts no test fails; on a change that touches no test, `--fast` passes its changed-tests step with a note). Steps come from `"dialecte": { "gate" }` in package.json or the defaults (`--full` runs the whole suite with the runner's defaults, `npx vitest run`: every file in parallel); `generatedDocs` are restored byte for byte after the docs build. While a hand-over holds the repository it runs only under the hand-over written for it (the script the lock names exists and the `lots.json` beside it names this repository, real paths compared), saying so in one line with the `dialecte handover <lots.json> --rehash` that refreshes it once green, so an author re-gates after a late edit; it refuses under a hand-over of another repository, a script that is gone, a folder without a lots file, and while a real `handover run` of that folder is in progress (its `running.json` naming a live process; that refusal names the marker file, so a person can tell a pid reused by another process). A refusal names the script and the lock and says to run the hand-over first, or to hand the lock's path to the person who runs the repository.
- `gate`: a vitest test step that fails (on its exit code or its counts; not a stall, nor a step already run with `--no-file-parallelism`) is run once more with `--no-file-parallelism`, on the failing files its output named (through `npm run`, after one `--`; the whole step when it named none). Passing there, the step passes flagged: `serial rerun of <n> file(s): exit 0, <counts>  flaky in parallel`, one `flaky <file>` line under it per file, the note in the gate record. Failing there, it fails as `real failure: <why>`, the files still failing listed `failed <file>`, the rerun's last lines as the tail. `--json` carries each step's `rerun`.
- `dialecte gate --fast` starts with the hygiene of the worktree: nothing staged; no stash entry pushed on this worktree's branch since `dialecte worktree add` made it (the baseline keeps every stash entry it saw, so another session dropping one changes nothing; entries of other branches are only noted, naming their branch; without a baseline, or with one that cannot be read, a note); and every new file one the change declares (`--declare <path>`, repeatable; an undeclared one is a warning). A failure says what changed and how to look at it with read-only commands, their paths quoted.
- `dialecte new verb <namespace> <query|transaction> <name>`: scaffolds an extension verb of a dialecte package in the house style, with its types, a red table-driven test, its barrel export and its namespace registration.
- `dialecte handover <lots.json>`: prepares the guarded commit-by-lots hand-over a human runs and holds the repository until every lot is committed (`gate` runs only under it; a hand-over of another folder is refused, naming the script holding the repository and its lock). It refuses (writing nothing) another branch or HEAD, a `core.hooksPath` naming a folder that does not exist (git would skip every hook: it says how to restore it), a staged file, a changed file in no lot or in two, plan tags and standard citations in files and messages. It writes the hand-over folder - the lots file, the snapshot (`files.txt`, `files.sha256`, `files.deleted`, and `lots.sha256`: an edit of `lots.json` after the review is refused) and a one-line `commit.sh` running `npx --no-install @dialecte/cli handover run <folder>` (bash re-exec; when the repository installs no cli that can run it, one line says so with the fix), nothing per lot - and prints the hand-over card and the command with its absolute `cd`; `--json` answers the same as data. `--rehash` after an edit.
- `dialecte skills check` refuses a method whose JSDoc summary or `@intent` still holds the `FILL:` placeholder `new verb` writes.
- `dialecte skills check`: fails when a skill cites an API, a path or an npm script that does not exist, links to a missing page, has invalid frontmatter or a stale generated block, or when a public method the package defines has no JSDoc summary or no `@intent` tag. It warns when a summary or an intent quotes a sentence, since the generated pages republish the JSDoc. `--workspace <folder>` also verifies pages that describe several repositories.
