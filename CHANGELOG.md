# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- `--help` (or `-h`) after any command prints the help and runs nothing: `dialecte bench --help` no longer runs the bench and rewrites the baseline.

### Changed

- The cli no longer re-declares core's types: the definition, record and reader shapes are type-only imports from `@dialecte/core` (devDependency, erased from the build; the bin still loads the core of the user's project at run time).
- `@xmldom/xmldom` (exact version) is a devDependency: the `fixture` tests parse the documents they check in Node with it. The test workflow installs `xmllint` (`libxml2-utils`): the `fixture` tests judge every document of core's test dialecte against the XSD core ships.

- **Breaking:** needs Node 22.18 or later (`engines`): `dialecte run` loads `.ts` scripts through Node's built-in type stripping.
- `@dialecte/core` (`^0.8.0`) is a devDependency: the `schema`, `run` and `explain` tests drive its test dialecte (`DIALECTE_CORE_DIR` overrides it with a local build). The lockfile picks it up at the release, once core 0.8.0 is published.
- `coverage` writes its temporary discovery file under `node_modules/.cache/dialecte/`, out of reach of formatters, linters and git.

### Added

- No silent hang: every child that `dialecte gate` (its steps), `tdd` (its vitest runs) and `handover run` (each commit and its hooks, `--rehearse` too) start runs in a process group of its own, with its stdin closed, under a stall watchdog. Output (a part of a line included) or CPU time gained by its tree (descendants and process group, sampled with `ps` every 5 s, with a timeout) counts as activity; after 10 minutes with neither, the tree is printed (pid, state, CPU time, command), stopped (SIGTERM, SIGKILL after 2 s) and the run ends once its processes are gone, as `stalled`: the gate's step `stalled: no output, no CPU for 10 m 0 s` with the tree in its tail, `tdd`'s run with the tree, a hand-over lot not committed and unstaged (or, when a stopped git's `index.lock` stays, reported as still staged with the lock to remove). A `ps` failing for the whole 10 minutes is a stall too. Ctrl-C, SIGTERM and SIGHUP are passed on to every running child's group (a rehearsal stops the hook's group before it removes its clone). A child asking the terminal (a gpg or ssh prompt) is in a background group: it stops (state `T`) and is reported as stalled. The gate's steps and `tdd`'s vitest run are no longer synchronous spawns.
- `dialecte tdd red|green|status [<test file> | <test file>::<case name>]... [--no-wait] [--json]`: a ledger in the worktree's git folder that makes the order of a lot's work visible. `red` runs every case of the changed test files with the package's own vitest (each project's run a case of its own; a browser package under the machine lock; snapshots never written): a failure on an assertion, a snapshot mismatch, a stub's `not implemented` or a TypeError of existing code, inside an `expect(...)` a matcher completes, is a red; a passing new or changed case, a case whose test call changed since its receipt, a failure on a missing export, a type or syntax error, a timeout, a stub thrown at import or before the assertion, and a file holding `.only` / `only: true` are refused with their reason; a case the same as at the base is marked unchanged. One refusal records no red of its file; refusals are kept in the ledger. Reds record the hashes of the test file, of the case's own test call and of the production files, and are flagged `rollback` (a production state the case had left) or `red after green`. The run freezes the test files without a refusal and the changed helpers, fixtures and snapshots. `green` refuses test code changed since its freeze ("tests are frozen after red; go back to the test station"), a case without a red receipt, a green with nothing changed in production since its red, and a failure. `status` prints each case with its flags, the test code changed outside `tdd red`, and the cases the change deletes. A ledger that cannot be read is refused with its path.
- `dialecte gate --fast` and `--full` run a `tdd` step after the hygiene: every test-code file changed since the base as the red run that last froze it, every case of the change red then green (or unchanged); the flags and deleted cases printed under the step. A lot declared exempt in `.dialecte/lot.json` (`{ "tdd": "exempt: <reason>" }`, never committed: the hygiene and the hand-over leave the file out, wherever the package sits in its repository) passes with its reason and the count of production and test files the change touches; the hand-over card shows the same and the flags. A package that does not test with vitest skips the step.
- The tdd red run refuses a passing case still waiting for its green whose test file or imported test code changed since its red ("test code changed since its red and it passes"); a green case kept at such a run is recorded and flagged `test code changed around it`. A helper, fixture or snapshot is frozen only by a red of a file depending on it (relative imports followed through test code, a file named in its text, its snapshot). An error any existing code throws inside an asserting `expect` is a red, not only a TypeError. `red after green` flags only a case whose own last receipt is a green at the same production state. `.dialecte/lot.json` may accept cases without a red (`"accept": [{ "case", "reason" }]`), shown with their reason by the gate and the hand-over card. `dialecte new verb` writes its red case without `only`.
- `tdd` measures the lot from HEAD: on a branch holding earlier committed lots, only the uncommitted work is the change. `tdd ... --base <ref>` and `gate --base <ref>` give the whole-branch view (from where HEAD left the ref); `gate --full` measures from where the branch left its base branch (before a merge). Test code is compared by the leaves of the parser's syntax tree (each file parsed by its extension: a `.ts` file is no TSX): whitespace, comments (except `@vitest-environment`, `@jest-environment` and `@vite-ignore` ones), quote style, statement semicolons, trailing commas after an element and the order of import statements between side-effect imports are formatting, not an edit; template literals are compared by their raw text; any other change is. The ledger format is version 3: a version-2 ledger is refused with the advice to move it aside. A repository without a commit is refused in one line. A file with a refused case still records its other cases' receipts (it stays unfrozen); `green` takes a red recorded in a file never frozen as it saw the file. `"dialecte": { "tdd": { "production": ["src/test"] } }` declares folders whose files are production code (a package's test entry), except the test files, fixtures, snapshots and `*.script.ts` under them. `testCase.only ? it.only : it` (a runner picking per row) is no focus marker; a call through `.only` and `only: true` still are. `.dialecte/lot.json` may declare cases revised at review (`"revised": [{ "case", "reason" }]`; the case needs an earlier receipt, not necessarily a red): the next `tdd red` records a passing revised case as `revised` (a failing one is a red) and freezes the file again; status, the gate step and the hand-over card show them with their reason, and an entry no red run used as a note. `handover run --rehearse` removes the folders a deleted file leaves empty in the clone.
- The tdd test dependencies follow imports through the package's tsconfig `paths` and vite `resolve.alias` (barrels and re-exports included); a bare package name is never test code, and an import that looks local and resolves nowhere refuses its file at `tdd red`, naming it. The lot file is strict (unknown keys and an exemption without a reason are refused); the hand-over card lists the accepted receipts of the ledger, marking those whose entry left the lot file, and the gate and the card report an acceptance no case used.
- Station agents `dialecte-test-writer` (standard: writes the tests and the stubs of a brief step, proves them with `tdd red`) and `dialecte-test-reviewer` (strong, read-only: the tests against the brief before any code); the implementers change production code until `tdd green`.
- `dialecte handover run <folder> [--rehearse [--keep]]`: the hand-over runner `commit.sh` calls. Each guard (repository, hooks folder, branch, HEAD, empty index, the snapshot, deleted files, files outside the lots, plan tags and citations in files and messages) prints one line with its result and its time; then `lot n/N` with its files and subject, the commit's hook output streamed behind a prefix with a heartbeat every 30 s while it is silent (after three silent beats, it asks whether the hook waits for input or runs in watch mode), the commit with its stat, the total time and the card. A lot whose `git add` or commit fails is unstaged again, and the same command resumes at it (a run stopped after staging its next lot is refused with the command that unstages it): lots already committed on top of the recorded HEAD (same message, same paths, same content) are skipped, anything else there is refused with what was found. `--rehearse` commits the lots in a scratch clone that looks like your tree (the repository at HEAD, the working tree on top, the hooks folder, a copy-on-write copy of `node_modules`), reports each lot and removes the clone (`--keep` keeps it), also on Ctrl-C or SIGTERM, with the hook and its processes stopped (an interrupted `node_modules` copy stops there, without a second copy); the clone holds a marker naming its process.
- `dialecte handover list [--root <dir>] [--json]`: every hand-over folder under the workspace's `_commit-plan/` (or the folder given, or the current one), one line each - folder, repository, worktree, branch, lots, age, and its state: pending, partly committed, committed, or stale when something else moved the branch; a folder with a hand-written `commit*.sh` and no lots file shows as "legacy script, state unknown".
- `dialecte worktree add <repository> <branch> [--from <ref>] [--json]`: a worktree under the workspace's `.worktrees/<repository>-<branch tail>`, ready to work in - the hooks folder of `core.hooksPath` copied, the main checkout's `node_modules` copied copy-on-write where the file system can (links kept, a relative link to a sibling re-pointed), the hygiene baseline written - and its card. A new branch starts from `--from`, else the package's base branch (`"dialecte": { "baseBranch" }`, default `main`).
- `dialecte worktree prune [--root <workspace>] [--yes] [--json]`: per repository of the workspace, the worktrees and local branches whose commits are all in the base branch, the hand-over folders whose lots are all committed (never `_commit-plan` itself nor a folder holding other folders) and the rehearsal clones whose process is gone, each with its removal command (absolute `cd` first); `--yes` runs them after a confirmation on a terminal and refuses without one. Kept, with why: an unmerged branch, the branch the main checkout is on, a worktree a hand-over is pending in or with uncommitted changes, a branch whose reflog still reaches commits the base does not hold, a worktree or branch with no commit of its own in its reflog, a worktree holding ignored files `git worktree remove` would delete (beyond `node_modules`, `dist`, `.vitepress/cache`, `.vitepress/dist`, `.DS_Store` and the hooks folder; a long list counted), a rehearsal clone still running or without a marker. It reads worktrees with `git --no-optional-locks`, never rewriting an index.
- Station agents for Claude Code: `dialecte skills sync` writes `.claude/agents/dialecte-<station>.md` for the stations of `dialecte-lot` that spawn an agent (`implementer`, `implementer-strong`, `reviewer`, `fixer`, `eval-runner`, `grader`, `standard-reader`, `searcher`) when Claude Code is a target and the vendor is anthropic: the model from the `dialecte models` map (as the `sonnet` / `opus` / `haiku` alias Claude Code accepts), the tools of the station (the reviewer reads and runs the tests, it has no Write or Edit; the grader and the searcher only read), a short body naming the station, the skills to load and what never to do. Owned through the manifest (replaced on every sync, removed when no longer produced, a file of your own with the same name is reported and kept); `dialecte doctor` warns about a stale or missing one. Other hosts get no agent files yet.
- Session-start check: `skills sync` adds a Claude Code `SessionStart` hook running `npx --no-install @dialecte/cli doctor --brief` (the installed cli, never a download at a session start) to `.claude/settings.json`, inserted by a minimal text edit (`jsonc-parser`: the rest of your file stays byte for byte, comments and layout included), never duplicated, recorded in the manifest, removed with the claude target (a `settings.json` sync created is deleted when nothing else is left; after you edited the hook's text, only our handler is cut - a comment right next to it may go with it - and nothing is written when anything else would change); `--no-session-check` leaves it out. A `hooks` that is not an object, or a `SessionStart` that is not a list, is left untouched with a warning. Station agents and the hook are written only when `dialecte-lot` is installed for Claude Code. `dialecte doctor --brief` prints nothing when everything is in sync, otherwise one line per problem with its fix, and always exits 0.
- MCP server: see [`@dialecte/mcp`](https://github.com/dialecte/mcp). The read-only lookups' answer functions are exported at `@dialecte/cli/lookups` (with declaration files) for programs that serve them in another form.
- `dialecte models [--vendor <id>] [--json]`: which model each tier (`fast`, `standard`, `strong`, `frontier`) means for the vendor the project uses (anthropic, openai, google), with the date the rows were checked and what each tier is for, so agents name a tier and never a model. `dialecte skills sync` detects the vendor from the project (`.claude/`, `AGENTS.md` + `.codex/`, `.gemini/`; Copilot and Cursor host several vendors), asks on a terminal when it cannot tell, and remembers it as `vendor` in every `.dialecte-skills.json` of the project; `--vendor <id>` sets it without asking. A folder holding only the skills a sync wrote is no evidence of an agent. Without a terminal, only a first sync (no manifest) with nothing detected exits 2 naming `--vendor`; a project that already has a manifest and an ambiguous or empty detection keeps syncing without a vendor and is told how to set it.
- `dialecte skills sync`: installs the agent skills your dependencies ship in `skills/<name>/` into `.claude/skills` and `.agents/skills` (`--agent claude,copilot,agents`, `--copy` instead of links, `--from <folder>` to take them from local checkouts). Only what it installed is ever replaced or removed. Its manifest records the package and version each skill came from.
- `dialecte run <script.ts>`: runs a module script (its default export gets `{ project, doc, documentId, dialecte, helpers, utils }`) against an in-memory project of the installed dialecte and answers one outcome - the thrown error as code, key, detail, `meta` and the element's path, the input's import diagnostics, the operations per tag, what the script returned. `--in` imports a file first, `--out` writes the result, `--prepare` stages the first transaction and commits nothing (its operations and its callback's report), `--expect <file>` checks a JSON array of `{ tag, where?, under?, count? }` and names each one not met with the count found. Ids are seeded (`--seed`), `--now` freezes the clock: the same script, input and seed give the same outcome. `--json`, `--package`, `--timeout`. Exit 1 when the run failed or an expectation is not met. Records are counted as each commit merges them. Under `--prepare` every other write is refused and fails the run, even caught (a second transaction, a prepared commit, another document's transaction, the project's writes and raw database); in every mode a callback may not call `tx.commit`, `tx.finishStaging` or `tx.clearStagedOperations`. Needs `@dialecte/core` 0.8.0.
- `dialecte fixture <Tag> [--under A/B] [--package <name>] [--out <file>] [--json]`: the smallest XML document holding an element that is valid against the dialecte's full schema - structure, values, identity and references - built by the installed dialecte's engine with its hooks: the chain of parents from the root (the shortest, or the `--under` path), every child required on the way and the first branch of every required choice, the first variant of an element of an abstract type, a value for every required attribute and for text an empty value does not satisfy (fixed, default, else the first value the type takes, every facet checked: enumeration, pattern, length, range), each sampled value new in the document so unique and key fields never repeat, and for every reference a keyref checks the element it points at - one already planned when the values can meet, else one planted along the key's selector. The document is the plain export, without record-id marks. Ids are seeded and the clock frozen: the same command gives the same bytes. Exit 1 with the reason when there is none: an unknown tag (the closest named), a `--under` step its parent does not hold, a value it cannot make (the attribute named), a reference it cannot plant (the constraint named), a write the engine refuses. Needs `@dialecte/core` 0.8.0 (`requiredChoices`).
- `dialecte explain <code | key>`: what an error or diagnostic code means, when it is raised, the usual fix and the docs page, from the catalogues of the installed core and dialecte. `--json`; exit 1 for a code no catalogue knows.
- `dialecte skills generate`: rewrites the generated blocks of your skills from the source: verb map of your extensions, core method index, hook files, and the API index (`api`: every method with its JSDoc summary and `@intent` tags; `intents`: "when you need to... → use").
- `dialecte api find "<need>"` and `dialecte api show <path>`: find a method by what you need and read its contract (signature, summary, intents, routes, where it is declared, a call a caller can copy) from the `api.json` the installed packages ship, without the repositories. Methods rank by the words of the need their intents hold, then their summary, then their name.
- `dialecte members <expression>`: what `doc.query`, `doc.query.reference` or `tx.lifecycle.extract` hold, from the live types of your package, one line per member.
- `dialecte schema <Tag>`: parents, children with how often each may appear, attributes with their rules, text and xsi:type variants of an element of an installed dialecte, read through the core that dialecte resolves; an unknown tag answers the closest tag names.
- `dialecte doctor`: installed `@dialecte/*` versions, the core API generation of each dialecte (a warning when one runs on another core than your app), synced skills against node_modules (missing skills, copies of another version), local checkouts; each warning with the command that fixes it.
- `dialecte skills generate` writes `api.json` next to the page holding the API index, with each method's declared signature and one call: its JSDoc `@example` when short and calling the method, else a test call without test scaffolding in its arguments; `skills check` fails when it is missing or stale.
- `dialecte rules`: the code-rules self-check on the syntax tree of the changed files (or the files given): types outside `*.types.ts`, module constants outside `*.constants.ts`, functions declared as `const`, an `await` inside an argument, plan tags and standard citations are errors; positional parameters and abbreviated names are warnings. `--json` for a program.
- `dialecte rules` reports a test that takes the system's temporary folder itself as its root - `tmpdir()` handed to a call that lists or scans a folder, or given as a root option (`root`, `cwd`, `scratchRoot`...) - as an error: other tests and processes share that folder; a folder of the test's own (`mkdtempSync(join(tmpdir(), '<prefix>-'))`) fixes it.
- `dialecte gate [--fast | --full]`: runs the package's Definition of Done step by step, unfiltered, and judges each step on its exit code and the counts it printed (a test step that counts no test fails; on a change that touches no test, `--fast` passes its changed-tests step with a note). Steps come from `"dialecte": { "gate" }` in package.json or the defaults; `generatedDocs` are restored byte for byte after the docs build. Refuses to run while a hand-over script holds the repository.
- `dialecte gate --fast` starts with the hygiene of the worktree: nothing staged; no stash entry pushed on this worktree's branch since `dialecte worktree add` made it (the baseline keeps every stash entry it saw, so another session dropping one changes nothing; entries of other branches are only noted, naming their branch; without a baseline, or with one that cannot be read, a note); and every new file one the change declares (`--declare <path>`, repeatable; an undeclared one is a warning). A failure says what changed and how to look at it with read-only commands, their paths quoted.
- `dialecte gate --full` and every heavy gate step hold a machine-wide lock in your cache folder (`$DIALECTE_CACHE_DIR` overrides it): one heavy run at a time on a machine. A step is heavy when it says so (`"heavy"` in `"dialecte": { "gate" }`), when its command names a browser project, or when it is a test step of a package that runs its tests in a browser (a `@vitest/browser*` or playwright dependency, or a `browser` in its vitest / vite config). Another heavy run waits with a line every 30 s naming the holder (pid, command, start), or refuses with `--no-wait`. The lock appears whole (written aside, then linked into place). A lock whose process is gone, or whose pid now belongs to a process started at another time (read in the C locale and UTC; a `ps` that answers nothing never makes a holder look dead), is taken over under a short takeover lock, so only one caller replaces it. A lock file still being written is left alone; one that stays unreadable, or a takeover lock, is cleared once it is a few seconds old.
- `dialecte new verb <namespace> <query|transaction> <name>`: scaffolds an extension verb of a dialecte package in the house style, with its types, a red table-driven test, its barrel export and its namespace registration.
- `dialecte handover <lots.json>`: prepares the guarded commit-by-lots hand-over a human runs and locks the repository for `gate` until every lot is committed. It refuses (writing nothing) another branch or HEAD, a `core.hooksPath` naming a folder that does not exist (git would skip every hook: it says how to restore it), a staged file, a changed file in no lot or in two, plan tags and standard citations in files and messages. It writes the hand-over folder - the lots file, the snapshot (`files.txt`, `files.sha256`, `files.deleted`, and `lots.sha256`: an edit of `lots.json` after the review is refused) and a one-line `commit.sh` running `npx --no-install @dialecte/cli handover run <folder>` (bash re-exec; when the repository installs no cli that can run it, one line says so with the fix), nothing per lot - and prints the hand-over card: repository, worktree, branch, HEAD, gates, each lot with its files, lines added and removed and its subject, and the command with its absolute `cd`; boxed, plain when not a terminal; `--json` answers the same as data. `--rehash` after an edit.
- `dialecte skills check` refuses a method whose JSDoc summary or `@intent` still holds the `FILL:` placeholder `new verb` writes.
- `dialecte skills check`: fails when a skill cites an API, a path or an npm script that does not exist, links to a missing page, has invalid frontmatter or a stale generated block, or when a public method the package defines has no JSDoc summary or no `@intent` tag. It warns when a summary or an intent quotes a sentence, since the generated pages republish the JSDoc. `--workspace <folder>` also verifies pages that describe several repositories.

## [0.1.0] - 2026-10-14

### Changed

- **Breaking:** `coverage` reads enumerations from the attribute's datatype, as `@dialecte/create` 0.1 writes them: regenerate your dialecte, then your coverage files.

## [0.0.3] - 2026-09-29

### Fixed

- `bench` measures only your own types: library declaration files are skipped, so a library's typing or a library error no longer moves the numbers. Regenerate your baseline once with this version.
